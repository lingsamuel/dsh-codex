# DSH ChatGPT 首版设计

DSH ChatGPT 运行在独立的 DSH Profile 中。它使用原生 DSH 工作区、侧栏和聊天视图。插件在浏览器中把 Codex 项目和线程映射为 DSH 控制器的可观察列表，把分页轮次映射为 DSH 对话事件。工作区展开、正文、工具行、文件差异和主题由 DSH 原生视图绘制。

Host 连接 WSL 中已经运行的 Codex App Server，通过 `project/list`、`thread/list` 和 `thread/turns/list` 读取原生记录。已登记的项目使用原生项目 ID，其余线程按 `cwd` 展示。会话列表分页沿用 Codex 对旧历史的索引补齐行为。

DSH 的会话搜索调用 Codex `thread/search`，在内存清单补上此前未知的命中会话，正文摘要保留为当次搜索结果。分页会话内的搜索用 `thread/searchOccurrences` 取得原生消息位置，沿旧页游标加载尚未显示的轮次并滚动至聊天节点。

打开对话时，Host 通过认证后的 SSE 连接发送首次历史页，随后监听 Codex 原生历史文件的变化和 App Server 广播的线程状态。分页存储使用原生记录游标读取尾部新增内容，旧版 rollout 读取受变更影响的尾部轮次。浏览器接收新增或更新的条目及完成、失败、审批和问答等待状态，旧历史继续按需分页。

在当前 Codex 版本，直接订阅未保存的逐字增量需要恢复线程并改变会话的客户端状态。只读 Host 通过常规只读请求取得原生记录和全局状态，保持 CLI 自己的审批和问答流程。连接中断后重新取得一次尾部快照以补齐间隔。

首次状态及后续广播都更新 DSH 会话列表，Codex 等待状态通过 `uiSession.registerPendingInteraction` 提供给原生侧栏。DSH 的 `completionUnread` 投影自 Codex 的 `firstUnread`。清单和线程快照附带原生回执。App Server 的回执事件仅发给线程订阅者，因此被动浏览在本机额外观察原生回执数据库，只读未读 ID，初次同步后只推送差量。网页打开和切换会话时保留 Codex 的原生阅读状态。

侧栏独立连接同一个 daemon。在会话和项目事件到达后更新对应条目，只有标识的事件按需读取单条原生记录。目录重连时刷新一次以补齐离线期间的变动。

归档会话单独补齐。原生 Pinned 分组和归档状态进入 DSH 侧栏已有的置顶及筛选数据，归档行的查看操作直接打开原来的 Codex 线程。

子代理目录使用 `thread/list` 的 `parentThreadId` 筛选。打开父会话时加载直属子线程，展开嵌套分支时按需查询。子线程保留原生 ID，复用 DSH 的子代理菜单及聊天引用。

聊天沿已有历史游标读取较早轮次的简短摘要，供 DSH 原生轮次导航使用。打开未加载的轮次时使用原生轮次 ID 找到目标，沿同一历史窗口补齐正文。

轮次尾部汇总成功的 Codex 文件变更，与工具行共享补丁解析结果。相同路径的多次补丁保持原顺序，并由 DSH 的差异组件分别绘制。

会话详情按需读取 `thread/read` 与 `thread/goal/get`。目标事件更新已打开的详情，当前模型配置不回填到历史轮次。

浏览器通过 DSH 的同源 API 访问 Host，继续使用 DSH 默认的访问令牌和 Cookie。独立 Profile 使用项目本地目录，与日常 DSH 服务并行运行。项目和聊天历史由 Codex 持有。首次运行时 Host 先读取 Codex 的状态库清单，再在后台补齐尚未收进清单的旧会话。列表缓存保存在项目的运行目录，包含原生 ID、路径、标题、时间和 Codex 列表提供的预览。重启时可以先展示清单，再从原来的 Codex 端点刷新。完整消息和工具记录在打开会话时按需读取。

工作区展示使用单独的目录映射。大小写不同且文件系统确认同一目录的路径合并，显示名称取自实际目录项。Codex 原生工作目录和线程 ID 照原样提供。DSH 视图使用内存中的视图数据，生命周期与浏览器一致。

会话列表按原生线程 ID 合并同一页和跨页记录，保留服务端的返回顺序。打开会话时创建 DSH 所需的内存 Session 引用，加载更早的轮次时给新事件向前分配视图序号。空推理条目在生成视图前排除，原生消息的文字、ID 和时间用于回放。

后续交互接入直接沿用 Codex App Server 的发送、插话、停止和服务端请求。Windows 原生接入复用同一协议，前提是目标 Codex 实例提供共享端点。

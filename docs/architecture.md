# DSH ChatGPT 架构

DSH ChatGPT 通过独立的 DSH `codex` Profile 展示并操作本机 Codex 会话。浏览器通过 DSH 的同源接口访问 Host，Host 连接已运行的共享 Codex App Server。

| 组件 | 职责 |
| --- | --- |
| DSH Web 客户端 | 将 Codex 项目、线程和轮次映射为 DSH 的工作区、会话列表和对话事件。使用 DSH 原生视图渲染正文、工具记录、文件差异和主题 |
| 插件 Host | 适配 Codex 请求，缓存侧栏清单，通过 SSE 推送目录和会话更新，按线程串行提交写操作 |
| Codex | 持有项目、会话历史、模型、权限和执行状态 |

## 部署与访问

发行包通过 `dsh.bundle` 声明配置，由 DSH 原生安装器注册在 `codex` Profile。配置沿用 DSH Base 的共享服务，并停用由 Codex 接管的会话存储与沙箱策略。用户设置仍写入 Profile 自己的补丁层。打包入口生成包含 Host、Web 客户端和文件引用索引产物的 npm tarball。

浏览器通过 DSH 的同源 API 访问 Host，继续使用 DSH 默认的访问令牌和 Cookie。独立 Profile 可与日常 DSH 服务并行运行。项目和聊天历史由 Codex 持有。

Windows 原生接入复用同一协议，前提是目标 Codex 实例提供共享端点。

## 工作区与会话目录

### 清单、缓存和更新

Host 连接 WSL 中已经运行的 Codex App Server，通过 `project/list`、`thread/list` 和 `thread/turns/list` 读取原生记录。已登记的项目使用原生项目 ID，其余线程按 `cwd` 展示。会话列表分页沿用 Codex 对旧历史的索引补齐行为。会话列表按原生线程 ID 合并同一页和跨页记录，保留服务端的返回顺序。

首次运行时 Host 先读取 Codex 的状态库清单，再在后台补齐尚未收进清单的旧会话。列表缓存默认保存在 Profile 的插件数据目录，包含原生 ID、路径、标题、时间和 Codex 列表提供的预览。重启时可以先展示清单，再从原来的 Codex 端点刷新。完整消息和工具记录在打开会话时按需读取。

侧栏独立连接同一个 daemon。会话事件更新对应条目，项目事件只读取项目清单及原生顺序。浏览器打开时先展示缓存并验证一次原生清单，目录重连时刷新一次以补齐离线期间的变动。

收到会话卸载状态时，Host 先通过 `thread/read` 核对该条记录。已有历史的会话按原生摘要更新。Codex 明确报告会话已不存在时，Host 发出目录条目的移除更新。快速重连期间读回的空白草稿也沿用这条更新路径。

### 分组、排序和项目操作

工作区展示使用单独的目录映射。大小写不同且文件系统确认同一目录的路径合并，显示名称取自实际目录项。Codex 原生工作目录和线程 ID 照原样提供。侧栏先按 Codex 项目清单的顺序展示原生项目，再按最近一条未归档会话的更新时间降序展示自动生成的目录工作区。目录排序跳过未发送的空白草稿，因为 Codex 读回草稿时可能给出当前时间。清单和启动事件使用同一草稿判定。更新时间相同或缺失时按目录 ID 决定相对顺序。DSH 视图使用内存中的视图数据，生命周期与浏览器一致。

原生 DSH 工作区控制器把项目改名、拖动和删除写入 `project/update`、`project/move` 和 `project/delete`。操作响应和 `project/changed` 事件使用同一原生项目清单。删除仅解除项目归属，会话按工作目录回到目录分组。

目录接收网页创建响应、Codex 会话增量或重新读取清单时，按原生创建时间识别当前页面打开后新增的会话。首次实时订阅补齐此前开始读取的完整清单，原生会话 ID 的毫秒时间用于区分同秒创建的会话。网页分叉的成功响应也能确认会话是新建的。每个新增会话只更新一次所属工作区和不分组列表的手动顺序，置顶分区由 DSH 渲染。初次加载和补齐的旧会话沿用既有顺序。

### 搜索、归档和子会话

DSH 的会话搜索调用 Codex `thread/search`，按侧栏归档筛选读取对应范围，补齐内存清单中未知的命中会话，并保留当次正文摘要。搜索结果通过原生会话导航打开，归档标记来自 Codex 清单。分页会话内的搜索用 `thread/searchOccurrences` 取得原生消息位置，沿旧页游标加载尚未显示的轮次并滚动至聊天节点。

归档会话单独补齐。原生 Pinned 分组和归档状态进入 DSH 侧栏已有的置顶及筛选数据。归档会话行的点击和键盘激活直接打开原来的 Codex 线程。置顶沿用原生分组操作，拖动沿用 DSH 视图的手动顺序。

子代理目录使用 `thread/list` 的 `parentThreadId` 筛选。打开父会话时加载直属子线程，展开嵌套分支时按需查询。子线程保留原生 ID，父子关系投影到 DSH 的会话摘要，使子代理树和面包屑共用原生导航。

## 会话历史与实时同步

### 分页和轮次定位

打开会话时创建 DSH 所需的内存 Session 引用，加载更早的轮次时给新事件向前分配视图序号。空推理条目在生成视图前排除，原生消息的文字、ID 和时间用于回放。

聊天沿已有历史游标读取较早轮次的简短摘要，供 DSH 原生轮次导航使用。打开未加载的轮次时使用原生轮次 ID 找到目标，沿同一历史窗口补齐正文。

### 实时连接与补齐

打开对话时，Host 通过认证后的 SSE 连接发送首次历史页，随后监听 Codex 原生历史文件的变化和 App Server 广播的线程状态。分页存储使用原生记录游标读取尾部新增内容，旧版 rollout 读取受变更影响的尾部轮次。浏览器接收新增或更新的条目及完成、失败、审批和问答等待状态，旧历史继续按需分页。

在当前 Codex 版本，直接订阅未保存的逐字增量需要恢复线程并改变会话的客户端状态。只读 Host 通过常规只读请求取得原生记录和全局状态，保持 CLI 自己的审批和问答流程。连接中断后重新取得一次尾部快照以补齐间隔。

最近会话和草稿引用可以保留已加载的历史与本地状态。只有需要实时数据的引用才持有会话的 SSE 连接，最后一个此类引用释放后关闭连接，并取消该连接正在补读的历史页。重新打开时，通过原有历史快照、分页游标和已处理的条目游标补齐切走期间的变化，侧栏状态继续由独立的目录订阅维护。

### 阅读回执和等待状态

首次状态及后续广播都更新 DSH 会话列表，Codex 等待状态通过 `uiSession.registerPendingInteraction` 提供给原生侧栏。DSH 的 `completionUnread` 投影自 Codex 的 `firstUnread`。App Server 0.171.0 广播原生回执变更，本机只读回执监听还补足通知行为不同的版本。可用于确认阅读的回执版本随相应历史快照发送，后续版本在其对应历史增量之后发送。主动打开的会话只有在前台看到最新消息后才提交确认。手动标未读保留到下次打开，回执冲突等新的消息实际显示后处理。

### 工具记录和文件差异

轮次尾部汇总成功的 Codex 文件变更，与工具行共享补丁解析结果。单文件汇总展开后直接显示 DSH 差异卡。多文件汇总展开后先列出前四个文件，可以显示全部文件行，点选后只渲染该文件的差异。相同路径的多次补丁按原顺序分别展示。无法解析的补丁保留路径和原文。

部分取消的请求只在 rollout 中留下原始工具调用和用户取消结果。历史监听按原生调用 ID 关联这两条记录，并把它们投影到对应轮次的工具行。原生回退通过同一 rollout 观察移除这些条目。

## 会话写入与执行

### 写入连接和按需恢复

网页操作使用短连接。同一 Host 按线程串行提交可能改变运行时或历史的操作。冷恢复后提交消息时短暂保留订阅，给原生轮次从接纳到开始留出时间。历史观察保持独立的只读连接。

新建通过 `thread/start` 建立 Codex 运行时。旧会话可以直接输入草稿，Host 在提交普通消息、异步答复、继续队列或修改历史时按需调用 `thread/resume`。继续队列保留恢复前选定的队列项，避免恢复已经启动该项时重复提交。修改历史以用户发起操作时的历史头为准，冷恢复前检查待发项，恢复后重新检查空闲状态和历史头。

打开归档会话时会读取原生历史，文本、模型和权限选择留在网页草稿里。明确发送或继续队列时，Host 在同一线程的串行操作中验证草稿设置并通过原生目录确认归档状态。执行必要的 `thread/unarchive` 后，模型、推理强度和权限随 `thread/resume` 传入，使冷恢复后原生自动领取的旧队列使用所选设置。原生队列在取消归档后可读取，继续队列仍在恢复前选定目标项。

### 发送、队列和会话标题

DSH 的忙碌时 Enter 设置决定发送模式。普通发送和排队使用 `thread/queue/add`。空闲会话发送后如果该消息仍是唯一待发项，Host 通过 `thread/queue/start` 让 Codex 确认能否启动，以恢复中断后暂停的空队列。已有待发项继续沿用原生队列顺序。只有同时看到线程运行和活动轮次时才提供插话，提交时通过 `turn/steer` 携带目标轮次 ID。停止通过 `turn/interrupt` 保留并暂停原生队列。队列通过原生 API 回读，文件变更和原生通知只作失效提示。

发送期间输入框隐藏已提交的文本，草稿继续由 DSH 原生编辑器保管。HTTP 回执、原生历史或队列确认送达时清空草稿。网络失败或等待确认超过 25 秒且未观察到送达时，原生编辑器重新显示原稿。

输入栏在 DSH 原生草稿中预览粘贴、选择或拖入的图片。提交时把草稿图片编码为 Codex 内嵌 `image` 输入，正文和图片一起由原生队列或活动轮次接收。待发缩略图随队列快照更新，已发送图片通过原生历史附件引用显示。编辑待发正文复用原生队列更新，沿用已有附件。

网页发送未命名会话的首条正文后，Host 读回 Codex 保存的原生消息，再用同一个 App Server 创建只读临时会话拟标题。临时会话关闭工具和 MCP，最多运行一个结构化推理轮次。生成失败时使用正文摘录。标题通过原生改名接口保存，保存前再次确认首条消息和现有名称。网页的手动改名与自动写入复用同一会话的提交顺序。侧栏用原生改名广播刷新标题。

### 审批和问答

当前查看的会话进入待答或待审批状态时，Host 临时加入这个已加载的线程，重放请求并用原始请求 ID 转交回答或决定。网页审批使用 DSH 原生审批卡。Codex 的解析通知关闭面板，CLI 可以处理同一个请求。

### 模型和权限

会话管理复用 DSH 同源连接，转发原生回执更新、改名、置顶和模型设置。模型选择器复用 DSH 原生组件，调用 Codex `model/list` 获取当前 provider 的模型和推理等级，对已加载的线程提交 `thread/settings/update`。未加载会话的模型选择保存在网页会话草稿中，发送或编辑后重发时确认 Codex 已应用设置再提交消息。网页旁路跟随原生设置落盘后读取当前值，历史轮次保持原来的模型信息。

权限选择器由 `permissionProfile/list` 提供目录。当前线程在明确选择后应用预设，并显示 Codex 确认的会话设置或已保存的上一轮设置。网页新建的空白线程保留 `thread/start` 的订阅，直到首轮开始、线程关闭或 Host 停止，以接收 `thread/settings/updated`。Host 重启前创建的草稿或其他客户端创建的空白线程缺少此订阅，只能确认 Codex 接收了更改。通用设置只保存此 Web profile 的新会话默认值，通过 `thread/start` 应用到新线程。

运行中，输入栏按活动轮次 ID 核对 rollout 中的 `turn_context`，显示该轮权限记录。后续轮次的预设仍来自原生会话设置。轮次记录缺失时，界面显示本轮权限未确认。`/permissions` 打开同一个输入栏选择器，沿用原生菜单和确认流程。

## 会话命令与后台任务

### 命令执行与状态投影

原生 DSH 命令菜单提供 `/status`、`/goal`、`/ps`、`/rename`、`/compact`、`/review`、`/plan` 和 `/permissions`。状态读取 `thread/read`，后台终端读取 `thread/backgroundTerminals/list`，改名复用原生会话弹窗。

命令提交复用按线程串行的同源流程。`/compact` 和 `/review` 在原生空闲线程上开启轮次，历史投影复用 DSH 压缩行和 Markdown。冷恢复前读取原生待发队列，发现待发项则交由用户处理。`/plan` 读取 Codex 协作模式目录，显式切换时应用 `thread/settings/update`。当前模式来自原生设置通知和已落盘的检查点。`/goal` 用 `thread/goal/get` 读取，用带用户来源的原生请求创建、暂停、恢复或清除，面板跟随目标通知。写操作回执按线程修订号校验，避免覆盖期间送达的更新。

DSH 的任务清单投影自原生 rollout 中已确认的 `update_plan` 调用。上下文占用来自同一原生记录的最近上下文 token 总量与模型窗口容量，在原生输入栏和 `/status` 中显示。一个读取连接内复用已扫描的字节位置，后续只读追加部分，保留 Codex 回退的语义。实时连接关闭时取消该连接的扫描，读取文件状态后再次检查取消信号，再开始读取内容。

### 后台终端

`/ps` 在 Codex 确认会话未加载时显示空列表。如果线程在读取列表前卸载，重新确认运行时状态后同样显示空列表。这些读取沿用只读连接。

后台进程的侧栏标记和原生会话面板共享 Host 扫描。首个目录订阅建立时立即读取 `thread/loaded/list`，然后以有限并发读取已加载会话的后台终端。扫描完成后间隔 10 秒继续，最后一个浏览器离开时停止。快照发生变化时通过目录 SSE 发给各网页。停止单个进程调用 `thread/backgroundTerminals/terminate` 并立即回读该会话的进程。扫描和停止的结果按执行顺序推送，读取全程无需恢复线程。

## 工作区文件与内嵌预览

### 本地文件与路径引用

浏览器投影把 Codex 的本地 URI 和行号转换为 DSH 支持的写法，复制操作沿用 DSH 显示的链接目标。右侧预览复用 DSH Workspace Files 的读取、分页和渲染，文件作用域只从 Codex 线程读取工作目录。文件读取服务不需要创建 DSH 会话或会话存储。

输入栏 `@` 补全复用 DSH 的文件引用界面、路径语法和原生目录索引。Host 使用同一文件作用域选择索引根目录。选中的文件和目录引用随文本进入原生消息或队列，Codex 按会话权限读取目标。

### Visualize

在 DSH 聊天正文里回放 Codex 已有的 Visualize 内容。按原生历史格式识别助手回复中独立成行的 Visualize 引用，复用 DSH 的 Markdown 扩展点，在引用原位展示预览。历史分页和实时消息使用同一投影。代码块里的引用示例继续显示为代码。

Host 通过 DSH 已认证的同源入口和现有文件读取权限取得引用的本地 HTML 片段。Host 用 Python 3 运行 Codex 插件缓存中的 Visualize 渲染脚本，通过 JSON 返回预览文档。片段的样式、脚本和交互在隔离来源的沙箱 iframe 中运行。普通预览随消息宽度显示，`mode: wide` 提供展开查看，`title` 用作预览标题。文件不可读、片段无效或本机缺少渲染器时，在引用处显示对应的错误状态。

用会话 `01a2026a-12ef-7be0-a801-af96e0e39142` 验收。重新打开会话后，原回复应内嵌显示月相预览，点击「蛾眉月」「上弦月」「满月」可以切换内容。另验证同一回复有多个预览、预览文件缺失以及代码块里的引用示例。

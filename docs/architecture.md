# DSH ChatGPT 首版设计

DSH ChatGPT 运行在独立的 DSH Profile 中。它使用原生 DSH 工作区、侧栏和聊天视图。插件在浏览器中把 Codex 项目和线程映射为 DSH 控制器的可观察列表，把分页轮次映射为 DSH 对话事件。工作区展开、正文、工具行、文件差异和主题由 DSH 原生视图绘制。

Host 连接 WSL 中已经运行的 Codex App Server，通过 `project/list`、`thread/list` 和 `thread/turns/list` 读取原生记录。已登记的项目使用原生项目 ID，其余线程按 `cwd` 展示。会话列表分页沿用 Codex 对旧历史的索引补齐行为。

DSH 的会话搜索调用 Codex `thread/search`，在内存清单补上此前未知的命中会话，正文摘要保留为当次搜索结果。分页会话内的搜索用 `thread/searchOccurrences` 取得原生消息位置，沿旧页游标加载尚未显示的轮次并滚动至聊天节点。

打开对话时，Host 通过认证后的 SSE 连接发送首次历史页，随后监听 Codex 原生历史文件的变化和 App Server 广播的线程状态。分页存储使用原生记录游标读取尾部新增内容，旧版 rollout 读取受变更影响的尾部轮次。浏览器接收新增或更新的条目及完成、失败、审批和问答等待状态，旧历史继续按需分页。

在当前 Codex 版本，直接订阅未保存的逐字增量需要恢复线程并改变会话的客户端状态。只读 Host 通过常规只读请求取得原生记录和全局状态，保持 CLI 自己的审批和问答流程。连接中断后重新取得一次尾部快照以补齐间隔。

首次状态及后续广播都更新 DSH 会话列表，Codex 等待状态通过 `uiSession.registerPendingInteraction` 提供给原生侧栏。DSH 的 `completionUnread` 投影自 Codex 的 `firstUnread`。App Server 0.171.0 广播原生回执变更，本机只读回执监听还补足通知行为不同的版本。可用于确认阅读的回执版本随相应历史快照发送，后续版本在其对应历史增量之后发送。主动打开的会话只有在前台看到最新消息后才提交确认。手动标未读保留到下次打开，回执冲突等新的消息实际显示后处理。

侧栏独立连接同一个 daemon。会话事件更新对应条目，项目事件只读取项目清单及原生顺序。浏览器打开时先展示缓存并验证一次原生清单，目录重连时刷新一次以补齐离线期间的变动。

归档会话单独补齐。原生 Pinned 分组和归档状态进入 DSH 侧栏已有的置顶及筛选数据，归档行的查看操作直接打开原来的 Codex 线程。

子代理目录使用 `thread/list` 的 `parentThreadId` 筛选。打开父会话时加载直属子线程，展开嵌套分支时按需查询。子线程保留原生 ID，父子关系投影到 DSH 的会话摘要，使子代理树和面包屑共用原生导航。

聊天沿已有历史游标读取较早轮次的简短摘要，供 DSH 原生轮次导航使用。打开未加载的轮次时使用原生轮次 ID 找到目标，沿同一历史窗口补齐正文。

轮次尾部汇总成功的 Codex 文件变更，与工具行共享补丁解析结果。相同路径的多次补丁保持原顺序，并由 DSH 的差异组件分别绘制。

原生 DSH 命令菜单按需执行 `/status`、`/goal`、`/ps` 和 `/rename`。状态读取 `thread/read`，目标读取 `thread/goal/get` 并消费实时通知，后台终端读取 `thread/backgroundTerminals/list`，改名复用原生会话弹窗。

DSH 的任务清单投影自原生 rollout 中已确认的 `update_plan` 调用。上下文占用来自同一原生记录的最近上下文 token 总量与模型窗口容量，在原生输入栏和 `/status` 中显示。一个读取连接内复用已扫描的字节位置，后续只读追加部分，保留 Codex 回退的语义。

浏览器投影把 Codex 的本地 URI 和行号转换为 DSH 支持的写法，复制操作沿用 DSH 显示的链接目标。右侧预览复用 DSH Workspace Files 的读取、分页和渲染，文件作用域只从 Codex 线程读取工作目录。文件读取服务不需要创建 DSH 会话或会话存储。

浏览器通过 DSH 的同源 API 访问 Host，继续使用 DSH 默认的访问令牌和 Cookie。独立 Profile 使用项目本地目录，与日常 DSH 服务并行运行。项目和聊天历史由 Codex 持有。首次运行时 Host 先读取 Codex 的状态库清单，再在后台补齐尚未收进清单的旧会话。列表缓存保存在项目的运行目录，包含原生 ID、路径、标题、时间和 Codex 列表提供的预览。重启时可以先展示清单，再从原来的 Codex 端点刷新。完整消息和工具记录在打开会话时按需读取。

工作区展示使用单独的目录映射。大小写不同且文件系统确认同一目录的路径合并，显示名称取自实际目录项。Codex 原生工作目录和线程 ID 照原样提供。DSH 视图使用内存中的视图数据，生命周期与浏览器一致。

会话列表按原生线程 ID 合并同一页和跨页记录，保留服务端的返回顺序。打开会话时创建 DSH 所需的内存 Session 引用，加载更早的轮次时给新事件向前分配视图序号。空推理条目在生成视图前排除，原生消息的文字、ID 和时间用于回放。

新建和继续通过 `thread/start` 与 `thread/resume` 建立 Codex 运行时。DSH 的忙碌时 Enter 设置决定发送模式。普通发送和排队使用 `thread/queue/add`，由 Codex 在空闲时接纳；直接插话调用 `turn/steer` 并携带目标轮次 ID。停止通过 `turn/interrupt` 保留并暂停原生队列，手动继续调用 `thread/queue/start`。队列通过原生 API 回读，文件变更和原生通知只作失效提示。

网页操作使用短连接，历史观察保持独立的只读连接。当前查看的会话进入待答状态时，Host 临时加入这个已加载的线程，重放待答请求并按原始请求 ID 回复。原生解析通知关闭 DSH 面板，CLI 也可处理同一请求。原生待处理的普通审批可以在 CLI 连接后接收。Windows 原生接入复用同一协议，前提是目标 Codex 实例提供共享端点。

会话管理复用 DSH 同源连接，转发原生回执更新、改名、置顶和模型设置。模型选择器复用 DSH 原生组件，调用 Codex `model/list` 获取当前 provider 的模型和推理等级，对已加载的线程提交 `thread/settings/update`。网页旁路跟随原生设置落盘后读取当前值，历史轮次保持原来的模型信息。

## Visualize 内嵌预览

在 DSH 聊天正文里回放 Codex 已有的 Visualize 内容。按原生历史格式识别助手回复中独立成行的 Visualize 引用，复用 DSH 的 Markdown 扩展点，在引用原位展示预览。历史分页和实时消息使用同一投影。代码块里的引用示例继续显示为代码。

Host 通过 DSH 已认证的同源入口和现有文件读取权限取得引用的本地 HTML 片段。Host 用 Python 3 运行 Codex 插件缓存中的 Visualize 渲染脚本，通过 JSON 返回预览文档。片段的样式、脚本和交互在隔离来源的沙箱 iframe 中运行。普通预览随消息宽度显示，`mode: wide` 提供展开查看，`title` 用作预览标题。文件不可读、片段无效或本机缺少渲染器时，在引用处显示对应的错误状态。

用会话 `01a2026a-12ef-7be0-a801-af96e0e39142` 验收。重新打开会话后，原回复应内嵌显示月相预览，点击「蛾眉月」「上弦月」「满月」可以切换内容。另验证同一回复有多个预览、预览文件缺失以及代码块里的引用示例。

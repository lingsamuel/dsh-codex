# DSH ChatGPT 架构

DSH ChatGPT 通过独立的 DSH `codex` Profile 展示并操作本机 Codex 会话。浏览器通过 DSH 的同源接口访问 Host，Host 连接已运行的共享 Codex App Server。

| 组件 | 职责 |
| --- | --- |
| DSH Web 客户端 | 将 Codex 项目、线程和轮次映射为 DSH 的工作区、会话列表和对话事件。使用 DSH 原生视图渲染正文、工具记录、文件差异和主题 |
| 插件 Host | 适配 Codex 请求，缓存侧栏清单，通过 SSE 推送目录和会话更新，按线程串行提交写操作 |
| Codex | 持有项目、会话历史、模型、权限和执行状态 |

## 部署与访问

发行包通过 `dsh.bundle` 将插件配置注册到 `codex` Profile。Profile 沿用 DSH Base 的共享服务，把会话持久化和沙箱策略交给 Codex，用户设置仍写入该 Profile 的补丁层。浏览器使用 DSH 的访问令牌和 Cookie 访问同源 API，默认服务地址为 `127.0.0.1:3190`。

## 工作区与会话目录

### 清单、缓存和更新

Host 使用 `project/list` 和 `thread/list` 读取目录，为分页结果按原生线程 ID 去重，并沿用 Codex 的旧历史索引补齐机制。列表缓存默认放在 Profile 的插件数据目录，包含原生 ID、路径、标题、时间和预览。浏览器先展示缓存，再从 App Server 刷新清单。

侧栏有独立的目录订阅。会话事件更新对应条目，项目事件刷新原生项目清单和顺序，目录重连时刷新清单以补齐离线变动。

收到会话卸载状态时，Host 先通过 `thread/read` 核对该条记录。已有历史的会话按原生摘要更新。Codex 明确报告会话已不存在时，Host 发出目录条目的移除更新。快速重连期间读回的原生空会话也沿用这条更新路径。

### 分组、排序和项目操作

打开「新建」时，浏览器为当前标签页和工作区复用占位会话。只保存占位的目录和 ID，正文及附件使用 DSH 原生输入栏的生命周期。占位不连接 Codex 历史流。

新会话的工作树选择保存在网页草稿。首条消息提交时，Host 由 Git 确认目标检出，按需创建工作树，再用目标目录和原项目 ID 启动 Codex 会话。切换已有会话会复查原生轮次、队列和后台进程，Codex 确认新目录后刷新目录索引。历史链接读得到轮次原目录时沿用该路径。

已登记的工作区使用原生项目 ID 和项目顺序，其余会话按 `cwd` 分组。目录映射会合并文件系统确认属于同一目录的大小写别名，并保留原生工作目录和线程 ID。自动目录按组内最近一条未归档会话的更新时间排序，跳过未发送的空白草稿。

原生 DSH 工作区控制器把项目改名、拖动和删除写入 `project/update`、`project/move` 和 `project/delete`。操作响应和 `project/changed` 事件使用同一原生项目清单。删除仅解除项目归属，会话按工作目录回到目录分组。

目录转为项目时，Host 登记或复用项目，串行迁移同目录的未分配会话，包括归档会话。迁移保留原有运行时和归档状态，重试只处理仍未分配项目的会话。操作回执和 `thread/project/updated` 共同更新目录。

目录接收网页创建响应、Codex 会话增量或重新读取清单时，按原生创建时间识别当前页面打开后新增的会话。首次实时订阅补齐此前开始读取的完整清单，原生会话 ID 的毫秒时间用于区分同秒创建的会话。网页分叉的成功响应也能确认会话是新建的。每个新增会话只更新一次所属工作区和不分组列表的手动顺序，置顶分区由 DSH 渲染。初次加载和补齐的旧会话沿用既有顺序。

### 搜索、归档和子会话

DSH 的会话搜索调用 Codex `thread/search`，按侧栏归档筛选读取对应范围，补齐内存清单中未知的命中会话，并保留当次正文摘要。搜索结果通过原生会话导航打开，归档标记来自 Codex 清单。分页会话内的搜索用 `thread/searchOccurrences` 取得原生消息位置，沿旧页游标加载尚未显示的轮次并滚动至聊天节点。

归档会话单独加载。侧栏置顶和归档筛选使用 Codex 原生分组与状态，拖动排序由 DSH 视图保存。

子代理目录使用 `thread/list` 的 `parentThreadId` 筛选。打开父会话时加载直属子线程，展开嵌套分支时按需查询。子线程进入运行状态时，目录订阅通过 `thread/read` 补齐父子关系，让已加载的分支在父轮次运行期间更新。子线程保留原生 ID，子代理树和面包屑共用原生导航。

## 会话历史与实时同步

### 分页和轮次定位

打开会话时创建 DSH 内存 Session 引用，通过 `thread/turns/list` 读取最新一页。重连时补齐实时窗口的缺口。需要查看更早历史时，DSH 原生「加载更早」使用当前游标请求一页，等聊天视图准备好后再向前插入，保留原生消息的文字、ID 和时间。

轮次导航根据已加载的正文生成。会话内搜索命中未加载的消息时，沿同一历史游标读取到原生轮次 ID，再定位到对应消息。历史窗口被替换时取消旧游标的分页请求。最后一个提供实时连接的引用释放后，也会取消尚未发布的旧页请求，已发布的页面仍可留在最近会话缓存中。

### 实时连接与补齐

打开对话时，Host 通过认证后的 SSE 连接发送首次历史页，随后监听 Codex 原生历史文件的变化和 App Server 广播的线程状态。共享历史库或 WAL 变化时，Host 只读核对当前 rollout 的投影检查点，变化时才通过 App Server 的原生游标读取新增内容。历史库不可读时仍可按文件变更提示重读。旧版历史跟随本会话的 rollout，分页回退换用新文件时会重新绑定。浏览器接收新增或更新的条目及完成、失败、审批和问答等待状态，旧历史继续按需分页。

每条 SSE 连接限制常规待发通知为 2 MiB，单个超过预算的通知可以分块发送。历史增量先交付当前原生页，再读下一页。页内按条目分帧，常规帧的 UTF-8 预算为 2 MiB，单条超大记录独占一帧。历史快照和增量帧按 64 KiB 网络块交给下游。活动轮次和窗口最新轮次保留原生条目，用于比较后续增量。发送积压时跳过心跳。再入队会超过预算时关闭该连接并释放监听，浏览器重连后补读历史或刷新目录。

轮次终态排在该轮相关增量之后。Host 先捕获线程级条目游标上界，再读取普通轮次，并逐页补发上界内的晚到条目。检查点和对应阅读回执在整批历史交付后发送。游标因回退失效时以权威快照替换窗口，未完成的增量由上次检查点重放。

目录读回 RPC 串行处理原生通知。读回前的等待队列最多保存 512 条、2 MiB，单条大通知可独占队列。App Server 意外断开会立即取消观察并废弃等待发送的数据。已收到的归档或取消归档通知通过原有连接送达后再重连。

浏览器用禁缓存的 Fetch 流读取 SSE，等当前帧成功投影后再解析下一帧。历史检查点在前序帧全部处理成功后生效。投影失败时撤回本次尚未发布的轮次合并和附件缓存更新。断开或投影失败时等待 3 秒，从最后一个已应用的检查点重连。等待网络数据时按收到的字节检测停更，投影耗时不计入空闲。会话在输入区上方显示实时同步中断，HTTP 补读历史和 SSE 建立都保留提示。收到并合并新连接的历史快照后收起提示。

浏览器按原生条目 ID 合并变更，保留未受影响的事件前缀，从首个受影响的条目继续转换。普通追加直接向 DSH 发布新增事件，完整事件窗口在按需读取时组装。影响事件顺序或既有内容的补录与回退会更新相应窗口。补录只重新投影受影响的已载入轮次，失败时保留这些轮次供重连重试。

重连时，移除失效历史轮次会一并删除插件缓存中对应的内嵌图片字节。保留的轮次继续提供附件读取。DSH 已创建的图片展示 URL 在原生会话绑定销毁时释放。

- [ ] DSH 上游提供按附件 ID 失效历史图片缓存的接口，供回退时撤销被移除图片的 Blob URL。复核中，DSH 0.2.3-alpha.2 在部分回退后仍持有 8 张已展示图片，合计约 1 MiB。验收时使用实际 DSH 图片缓存，确认回退后立即释放旧 URL、进行中的读取无法重新加入旧图片，并且保留轮次的图片仍可展示。

订阅未保存的逐字增量需要恢复线程并改变会话的客户端状态。常规观察使用只读请求和全局通知，CLI 继续处理自己的审批和问答。连接中断后读取尾部快照以补齐间隔。

最近会话和草稿引用可以保留已加载的历史与本地状态。只有需要实时数据的引用才持有会话的 SSE 连接，最后一个此类引用释放后关闭连接，并取消该连接正在补读的历史页。重新打开时，通过原有历史快照、分页游标和已处理的条目游标补齐切走期间的变化，侧栏状态继续由独立的目录订阅维护。

### 阅读回执和等待状态

首次状态及后续广播都更新 DSH 会话列表，Codex 等待状态通过 `uiSession.registerPendingInteraction` 提供给原生侧栏。DSH 的 `completionUnread` 投影自 Codex 的 `firstUnread`。App Server 0.171.0 广播原生回执变更，本机只读回执监听还补足通知行为不同的版本。可用于确认阅读的回执版本随相应历史快照发送，后续版本在其对应历史增量之后发送。主动打开的会话只有在前台看到最新消息后才提交确认。手动标未读保留到下次打开，回执冲突等新的消息实际显示后处理。

### 工具记录和文件差异

轮次文件改动汇总和工具行共享补丁解析结果。相同路径的多次补丁保留原有顺序，无法解析的补丁保留路径和原文。

部分取消的请求只在 rollout 中留下原始工具调用和用户取消结果。历史监听按原生调用 ID 关联这两条记录，并把它们投影到对应轮次的工具行。前端记住补录在原生条目之间的插入位置，后续增量从受影响的位置合并和转换。缺少时间的尾部条目保留原生顺序。未定位的补录放在最近一个有可靠时间的条目或轮首输入之后，并排在无时间的尾部之前，使后续无时间条目能继续增量追加。后续出现可靠的时间锚点时按时间重新定位，同 ID 的原生条目到达后合并为一条。原生回退通过同一 rollout 观察移除这些条目。

## 会话写入与执行

### 写入连接和按需恢复

网页操作使用短连接。同一 Host 按线程串行提交可能改变运行时或历史的操作。冷恢复后提交消息时短暂保留订阅，给原生轮次从接纳到开始留出时间。历史观察保持独立的只读连接。

普通发送、插话和问答提交复用 DSH 的本地气泡。短暂入队可确认提交，气泡继续显示直到同一提交 ID 的原生记录接手。Host 确认消息还需等待时，浏览器收到原生队列项后交接给队列。首发或工作树提交切换到原生会话时，未接手的回显随提交 ID 和预览一起迁移。

新会话首次发送、提交 Goal 或开始审查时通过 `thread/start` 建立 Codex 运行时。首发订阅在原生操作完成后释放。遗留创建订阅有 60 秒空闲期限，正在等待原生回执的操作按请求自己的期限结束，后台读取无需续期。旧会话可以直接输入草稿，Host 在提交普通消息、异步答复、继续队列或修改历史时按需调用 `thread/resume`。继续队列保留恢复前选定的队列项，避免恢复已经启动该项时重复提交。修改历史以用户发起操作时的历史头为准，冷恢复前检查待发项，恢复后重新检查空闲状态和历史头。

打开归档会话时会读取原生历史和只读待发队列，文本、模型和权限选择留在网页草稿里。明确发送或继续队列时，Host 在同一线程的串行操作中验证草稿设置并通过原生目录确认归档状态。执行必要的 `thread/unarchive` 后，模型、推理强度和权限随 `thread/resume` 传入，使冷恢复后原生自动领取的旧队列使用所选设置。继续队列仍在恢复前选定目标项。

### 发送、队列和会话标题

DSH 的忙碌时 Enter 设置决定发送模式。普通发送和排队使用 `thread/queue/add`。空闲会话发送后如果该消息仍是唯一待发项，Host 通过 `thread/queue/start` 让 Codex 确认能否启动，以恢复中断后暂停的空队列。已有待发项继续沿用原生队列顺序。只有同时看到线程运行和活动轮次时才提供插话，提交时通过 `turn/steer` 携带目标轮次 ID。停止通过 `turn/interrupt` 保留并暂停原生队列。共享队列库变更时，Host 核对目标会话的原生队列修订号后决定是否重读。修订号不可读时按文件提示重读，目标会话的原生通知也可直接触发刷新。Host 优先用 `thread/queue/list`，收到明确的归档拒绝时，队列观察流程才从本机原生队列库按线程只读查询。两条读取路径共用 DSH 队列投影。队列修改交由 App Server。

待发项插话是独立的队列操作。Host 先保留该项的完整原生输入，再取走原生待发项并向指定轮次提交。队列区域在等待时保留正文和附件，确认接纳后移除。Codex 明确拒绝时恢复待发项；断线导致结果不明时，重连按原生 `clientUserMessageId` 核对历史与队列。回读尚无送达证据时，副本在本次 Host 运行期间继续保留，用户可以再次核对或下载原生输入 JSON。输入栏草稿及其提交生命周期独立于待发项插话。

输入栏在 DSH 原生草稿中预览粘贴、选择或拖入的图片。提交时把草稿图片编码为 Codex 内嵌 `image` 输入，正文和图片一起由原生队列或活动轮次接收。待发缩略图随队列快照更新，已发送图片通过原生历史附件引用显示。编辑待发正文复用原生队列更新，沿用已有附件。

普通文件复用 DSH 原生浏览器上传进度和本地附件仓库。Host 按 SHA-256 去重保存原始字节，以保留文件名的硬链接给 Codex 提供受管路径。提交前校验归属当前会话的上传回执。原生队列和历史持有路径和文本元素，网页据此显示附件卡。下载前 Host 从对应队列项、待确认的插话原稿或历史消息读取引用，再从附件仓库流式返回文件。归档队列的展示和附件下载使用同一个只读快照。

网页发送未命名会话的首条正文后，Host 读回 Codex 保存的原生消息，再用同一个 App Server 创建只读临时会话拟标题。临时会话关闭工具和 MCP，最多运行一个结构化推理轮次。生成失败时使用正文摘录。标题通过原生改名接口保存，保存前再次确认首条消息和现有名称。网页的手动改名与自动写入复用同一会话的提交顺序。侧栏用原生改名广播刷新标题。

### 审批和问答

当前查看的会话进入待答或待审批状态时，Host 临时加入这个已加载的线程，重放请求并用原始请求 ID 转交回答或决定。网页审批使用 DSH 原生审批卡。Codex 的解析通知关闭面板，CLI 可以处理同一个请求。

实时问答复用 DSH 原生答题卡。只要一组题含有 Codex 标记为 `isSecret` 的题，该组的编辑状态就由面板在内存中保管，保密题的自由输入使用遮罩。面板卸载时丢弃草稿，提交时按原请求 ID 将答案交给 Codex。收到即时应答回执后，浏览器在当前历史窗口内将回显换成原生问答气泡。保密题在两处均只显示遮罩文案。

归档会话从最近轮次保存的原生条目构建异步答题卡。选择选项或编辑文字会写入网页草稿。明确提交时，Host 先用只读历史确认问题仍待答，再按需解除归档。随后先读原生队列、再核对历史，过滤其他客户端已经答复的题目。仍有答复时按需加载原会话，并用原问题身份插话或入队。入队后复用普通发送的队首启动和等待确认。

### 模型和权限

会话管理复用 DSH 同源连接，转发原生回执更新、改名、置顶和模型设置。模型选择器复用 DSH 原生组件，调用 Codex `model/list` 获取当前 provider 的模型和推理等级，对已加载的线程提交 `thread/settings/update`。未加载会话的模型选择保存在网页会话草稿中，发送或编辑后重发时确认 Codex 已应用设置再提交消息。网页旁路跟随原生设置落盘后读取当前值，历史轮次保持原来的模型信息。

权限选择器由 `permissionProfile/list` 提供目录。当前线程在明确选择后应用预设，并显示 Codex 确认的会话设置或已保存的上一轮设置。新会话按工作目录只读查询 Codex 配置，显示默认模型、推理档位和权限；网页默认权限优先。明确选择的设置在首次原生操作时应用。Host 在创建时使用显式预设或网页默认预设，通过 `thread/settings/updated` 等原生回执确认实际状态。

权限菜单旁的插话提示要求当前轮正在运行、原生输入草稿有正文、下轮设置与本轮权限有可确认的差异。提示的悬停说明按活动轮次 ID 核对 rollout 中的 `turn_context`，显示本轮权限记录。

### 技能、插件与 MCP

输入栏候选和结构化 `skill` 输入取自当前工作目录的 `skills/list`。消息在发送前以实际目标线程的目录重新核对。插件、App 与 MCP 管理通过 DSH 设置面板调用 Codex 原生目录和操作。MCP 表单和外部授权请求与审批共用按需加入会话的连接，沿用 Codex 原生请求身份及完成通知。

插件启停先通过 `plugin/read` 核对安装和管理策略，再沿用 CLI 的 `config/value/write`，以 Codex 返回的插件配置 ID 合并 `enabled`。列表、详情和 App 状态随后从 App Server 更新。

## 会话命令与后台任务

### Markdown 导出

导出通过同源只读入口从原生历史头向较旧轮次分页，运行中的旧格式会话直接读取已保存的原生轮次。已落盘 rollout 可补足被取消的工具记录。网页与导出共用轮次事件转换，导出将原生 Markdown 交给 DSH 的格式化工具，可复制或保存为文件。

### 命令执行与状态投影

原生 DSH 命令菜单提供 `/status`、`/goal`、`/ps`、`/rename`、`/compact`、`/review`、`/plan` 和 `/export`。状态读取 `thread/read`，后台终端读取 `thread/backgroundTerminals/list`，改名复用原生会话弹窗。

命令提交复用按线程串行的同源流程。`/compact` 和 `/review` 在原生空闲线程上开启轮次，历史投影复用 DSH 压缩行和 Markdown。冷恢复前读取原生待发队列，发现待发项则交由用户处理。`/plan` 直接切换协作模式，沿用 `collaborationMode/list` 和 `thread/settings/update`。输入栏标签跟随原生设置通知和已落盘的检查点。

`/goal` 是当前会话的输入草稿模式。发送时使用原生 Goal 操作并交由 DSH 确认或恢复草稿。替换已有目标先让用户确认实际目标身份，Host 再核对后写入。会话实时快照携带 `thread/goal/get` 的目标，后续跟随原生目标通知。DSH 原生 `ui-goal` 用同一会话投影渲染 GoalBar。写操作回执按线程修订号校验，避免覆盖期间送达的更新。已落盘目标和原生目标轮次关联后，在历史中补齐 `/goal` 用户气泡及命令高亮。目标达成提示使用原生通知或与目标匹配的工具回执中的累计用时。

带正文的 `/plan` 复用模式切换的原生确认，确认和入队在同一线程提交顺序内完成。Codex 保存的 `plan` 条目沿用会话的消息锚点，以文档卡展示。右侧栏根据会话、轮次和条目 ID 读取同一份历史，下载使用原始 Markdown。

DSH 的任务清单投影自原生 rollout 中已确认的 `update_plan` 调用。上下文占用来自同一原生记录的最近上下文 token 总量与模型窗口容量，在原生输入栏和 `/status` 中显示。实时连接复用已扫描的字节位置，追加记录只更新受影响的元数据字段。工作目录按轮次 ID 合并，SSE 只传新增、更正和移除的目录。回退时显式清除已删除轮次的补充记录，重连时重新读取当前 rollout。实时连接关闭时取消该连接的扫描。

### 后台终端

`/ps` 在 Codex 确认会话未加载时显示空列表。如果线程在读取列表前卸载，重新确认运行时状态后同样显示空列表。这些读取沿用只读连接。

后台进程的侧栏标记和原生会话面板共享 Host 扫描。首个目录订阅建立时立即读取 `thread/loaded/list`，然后以有限并发读取已加载会话的后台终端。扫描完成后间隔 10 秒继续，最后一个浏览器离开时停止。快照发生变化时通过目录 SSE 发给各网页。停止单个进程调用 `thread/backgroundTerminals/terminate` 并立即回读该会话的进程。扫描和停止的结果按执行顺序推送，读取全程无需恢复线程。

## 工作区文件与内嵌预览

### 本地文件与路径引用

浏览器投影把 Codex 的本地 URI 和行号转换为 DSH 支持的写法。投影先移除 Markdown 本地绝对路径开头的零宽空格，再按轮次工作目录解析相对路径。复制操作沿用 DSH 显示的链接目标，导出使用 Codex 保存的原始 Markdown。右侧原生文件树和预览共用 DSH Workspace Files，目录列表、搜索和文件读取的作用域取自 Codex 线程的工作目录。文件读取服务不需要创建 DSH 会话或会话存储。

输入栏 `@` 补全复用 DSH 的文件引用界面、路径语法和原生目录索引。Host 使用同一文件作用域选择索引根目录。选中的文件和目录引用随文本进入原生消息或队列，Codex 按会话权限读取目标。

输入栏同样可以搜索 Codex 会话，保存 `thread://` 引用及原生 UTF-8 文本范围。展示时用会话标题定位原线程，模型通过 `read_thread` 按需读取原生历史。新建网页会话和提交引用时需要冷恢复的会话携带线程级 MCP 配置。Codex App Server 负责启动会话工具，已有 CLI 会话的引用使用在线的原生工具。会话工具沿用 Codex 的九项会话 RPC 语义，创建、分支和向其他会话发送的审批经原生 MCP 询问流程处理。

图片悬停和 Markdown 内嵌图片使用原版 DSH 的同源媒体接口。它按绝对路径读取 Host 能访问的文件，使用文件版本缓存响应。文件和图片右键菜单由 DSH 提供，已打开的工作区文件通过 `workspaceFiles` 读取原始字节，再交给浏览器复制或下载。

### Visualize

历史与实时消息共用 Markdown 转换，识别助手回复中独立成行且位于代码块之外的 Visualize 引用。Host 通过已认证的同源入口和现有文件读取权限获取本地 HTML 片段，使用 Python 3 调用 Codex 插件缓存中的渲染器。浏览器在隔离来源的沙箱 iframe 内展示预览，渲染失败时在引用位置显示错误。

# Codex 会话历史自适应加载

## 加载行为

打开会话时优先显示最近的对话。首屏至少显示最近 3 轮，历史不足 3 轮时显示已有轮次。Host 检查候选轮次的原生条目数和存储字节数。如果最近 3 轮的完整详情超过预算，优先保证这几轮都有可读内容，再按从新到旧的顺序补入预算允许的详情。其余轮次用摘要显示。若仍有预算，则向前扩展连续的完整轮次，最多到「打开时加载轮数」。轻量会话可以在首屏完整显示这一窗口。

首屏绘制后，开启后台预读的会话自动从已显示历史前缘继续向前加载，直到达到「打开时加载轮数」或历史起点。目标按首屏和后台合计的轮数计算。后台使用小批次读取和交付，批次之间让出浏览器主线程。沿用现有历史分页的准备、合并和滚动定位，用户继续输入或滚动时优先响应操作。接近历史前缘时可直接消费已预读的数据。

点击「加载更早」时优先使用已准备的历史，并沿原生游标从近到远继续读，默认最多再加载 15 轮。每准备好一轮就向列表顶部发布，随后让浏览器绘制并继续下一轮。Host 可以在一次请求里分批交付多轮。浏览器为每次插入保留当时的阅读位置，用户可立即阅读已显示的轮次。加载状态持续到本次目标或历史起点，发生错误时保留已显示的轮次，下次从最后成功发布的位置继续。手动加载的总量可以超过首屏预算。

单轮超过可交付批次的预算时，先显示原生轮次摘要，完整条目从该轮的原生条目游标按需加载。单条摘要内容过大时先展示有界预览。摘要的消息保留原生身份，详情合并时按条目 ID 去重。搜索定位需要摘要中未显示的条目时，沿用该轮的明细读取。正在运行的轮次继续接收原有实时更新，摘要与已加载条目的状态随原生历史补齐。

## 设置

在「设置 → Codex on DSH」提供会话历史加载选项，沿用 DSH 的设置行、输入框、开关和 Profile 偏好存储。「打开时加载轮数」和「每次加载更早的轮数」分别设置，默认均为 15 轮。打开时的目标最少为 3 轮。首屏条目数和体积预算可调整，后台预读默认开启，可独立关闭。有效数字在按 Enter 或离开输入框时自动应用，开关切换后自动应用。下一次打开会话时采用新设置。

建议以 **1,000 个条目、1 MiB**作为首屏验收配置。任一预算达到时停止扩展完整轮次，有足够历史时仍显示最近至少 3 轮。调试中以浏览器点击到首次绘制和后台加载期间的交互延迟确定最终默认预算。

## 数据来源与取消

复用历史监听识别分页索引和 rollout 的方式。首屏可从当前 rollout 的原生历史索引只读统计各候选轮次的条目数和原始字节数，交付前以实际数据检查预算。索引不可用或候选结果失效时，分页历史使用原生轮次元数据和受限的条目页逐步测量。旧格式历史沿用 Codex 的原生读取路径，浏览器仍分批接收历史。

后台和手动加载共用当前历史前缘、原生游标和准备中的批次。手动操作接续准备中的工作，避免重复请求和重复发布。切换会话、释放视图或回退替换历史窗口时取消无效的预读。SSE 实时尾部独立跟随，背景进度不推进实时检查点。预读失败后保留当前已显示的历史和原生游标，手动操作可从该位置继续。

## 验收

- 用普通会话验证在首屏完整显示最近 15 轮。用首屏约 9.1 MiB 的真实会话对比首屏绘制时间，并验证随后自动向前补齐至目标。在后台运行时测量滚动、输入和切换会话的响应。
- 构造单轮条目过多与单条输出过大的会话，验证摘要可先出现、详情可继续加载、搜索能定位到摘要外的消息。逐批确认同一轮的原生顺序、ID 和阅读位置。
- 关闭预读，延迟手动加载的后续轮次。确认一次操作持续加载至目标，首轮能在后续数据仍未到达时显示，逐轮插入保留阅读位置。覆盖后续读取失败及从已发布的轮次继续。
- 在预读过程中触发手动加载、切换会话、断开重连和回退。检查游标连续、无重复轮次，失效结果不会发布。
- 验证设置持久化、不同 Profile 的隔离、索引无法使用时的原生分页，以及旧格式会话的历史可读性。

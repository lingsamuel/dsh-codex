# Codex 网页命令扩展设计

在 DSH 输入栏的「+」和 `/` 菜单中提供 `/compact`、`/review`、`/plan` 和 `/goal`。压缩和审查使用命令弹窗。目标和计划使用输入栏内联状态，会话结果以 Codex 为准。

## 命令行为

| 命令 | 网页交互 | Codex 行为 |
| --- | --- | --- |
| `/compact` | 在有历史的空闲会话执行，聊天中显示压缩进度和结果。上下文用量随 Codex 的新记录更新。 | 用 `thread/compact/start` 压缩当前会话上下文，沿用原生轮次与 `contextCompaction` 记录。 |
| `/review` | 先选择审查未提交的改动、相对指定分支的改动、指定提交或自定义审查要求。分支名、提交 ID 和审查要求按需填写。审查结果显示在当前聊天。 | 用 `review/start` 在当前会话启动审查。将原生审查开始和完成记录投影到聊天，最终结果用现有 Markdown 组件显示。 |
| `/plan` | 从命令菜单切换默认模式和计划模式。计划模式在输入框下方显示标签，点击 × 返回默认模式。 | 用 `collaborationMode/list` 读取可用模式，通过 `thread/settings/update` 应用于后续轮次。使用会话当前的模型与推理强度，按 Codex 确认的设置显示。 |
| `/goal` | 从命令菜单进入目标输入模式。在现有输入框编辑目标，点击下方 Goal 标签的 × 退出此次输入模式。发送成功后显示已保存目标的独立进度条。 | 用 `thread/goal/get`、`thread/goal/set` 和 `thread/goal/clear`，写操作带原生 `origin: user`。目标启动与继续执行由 Codex 调度，进度条跟随原生目标通知。 |

## 输入栏的 Goal 与 Plan

- 从「+」或 `/` 菜单选择 `/goal` 后，输入框下方显示 Goal 标签，焦点回到原生输入框。已有正文作为待提交目标，可以继续编辑。点 × 取消本次模式并保留草稿，下一次发送走普通消息流程。
- 目标复用原生输入栏的发送、错误和草稿恢复流程。提交正文及可选 token 预算，成功后退出目标输入模式并交由 Codex 执行。已有目标时，明确确认替换后才提交新目标。目标输入以文本为主，图片等附件或待建立的工作树继续保留在草稿中，遇到这些提交条件时在输入栏说明如何处理。
- 目标进度条复用 DSH 的 `GoalBar`，位于原生进度栏，与任务清单、待发队列同列。用 Codex 的会话目标投影驱动状态，将暂停、恢复、编辑与清除转到 Codex。清除前复用目标身份核对。使用一次原生写入变更目标正文、阶段或预算，按 Codex 回执显示记账结果。状态和预算从 Codex 读回，切换会话或重连时按该会话重新查询。
- `/plan` 的可叉掉标签沿用 DSH 输入栏的计划控件位置和风格。选择 Goal 时切回默认协作模式，进入 Plan 时收起尚未提交的 Goal 模式。已保存目标通过进度条的清除操作移除。
- Goal 和 Plan 共用输入栏位置与 DSH 按钮样式。标签平时显示模式图标，悬停或键盘聚焦时将同一位置替换为 ×。Goal 预算从命令菜单设置。Goal 提交的提示归属当前输入模式，退出时一并清除。

原生参考见 [ChatGPT 桌面端命令说明](https://learn.chatgpt.com/docs/reference/slash-commands#set-or-manage-a-goal-with-goal)。本机 Windows Codex 桌面端的 Goal 标签 × 只处理本次待提交的 Goal 输入模式，目标进度条另有持久目标的清除操作。

## 会话与错误处理

- 复用现有命令注册、经认证的同源 API 和按会话串行提交。表单或确认完成后提交明确的会话操作，始终使用打开命令时的线程 ID。与 Codex 的权限和审批交互沿用现有链路。
- `/compact` 和 `/review` 发起新轮次，提交时检查会话仍可操作且空闲。`/plan` 的设置作用于后续轮次。`/goal` 的暂停与清除可用于运行中的目标，适用状态由 Codex 确认。
- 打开菜单、审查表单或查看目标时按现有只读流程查询。需要运行时的操作在用户提交后才按需恢复。冷会话已有待发消息时提示先处理队列，因为 Codex 恢复线程可能自动领取队首。归档会话使用现有明确的取消归档操作后提交命令。
- 请求已接纳和实际执行结果分别由原生响应和后续记录体现。原生拒绝或连接失败时显示具体错误，保留表单内容。刷新和重连后用原生状态重建视图。

## 验收

- 从「+」和 `/` 菜单打开四个命令，切换会话后检查命令目标与草稿归属。
- 验证压缩和四种审查目标的原生请求、轮次回放，以及忙碌会话或已有待发消息时的反馈。
- 切换计划模式与默认模式，检查输入栏状态、后续轮次设置和重新打开会话后的显示。
- 用键盘开启 Goal，输入正文后按 ×，检查草稿和已有目标。分别验证提交成功、失败重试、已存在目标的替换，以及切换会话后的草稿归属。
- 创建、暂停、恢复、编辑和清除目标，验证原生 DSH 进度条与网页和 CLI 的同一目标同步。核对预算、重新打开和重连时的状态。

# 网页会话拟标题

## 设置

在「Codex on DSH」中提供「拟标题模型」和「随会话更新标题」，按 DSH Profile 保存。模型用于网页首次拟题和开启后的标题更新。默认项显示「GPT‑6 Luna（默认）」，对通过 ChatGPT 登录且目录提供 `gpt-6-luna` 的 OpenAI 会话使用低推理强度。菜单与新会话默认模型共用 Codex 当前配置的提供商目录，已经保存的模型继续按原提供商标识解析。所选模型不可用或请求失败时，未命名会话显示 Codex 正文预览，已有标题继续显示当前名称。自动更新默认关闭。 [GPT‑6 Luna 模型说明](https://developers.openai.com/api/docs/models/gpt-6-luna)

设置页说明拟题根据少量用户发言在后台单独请求所选模型。即使最后保留原标题，请求也可能增加订阅用量或 API 费用。模型的提供商与主会话可不同，发言由所选提供商处理。

## 首次拟题与后续更新

网页提交新会话首条含文字的消息后，Host 通过原生消息标识确认该消息已进入历史，再为尚未命名的会话拟题。纯图片、待发消息和重复提交沿用原生预览及现有去重规则。浏览器切换页面后，已开始的任务仍可完成。

开启更新后，DSH 网页中提交的用户正文才触发会话跟进，包括普通发送、领到正文的队列轮次、插话和编辑后重发。Host 用原生消息或轮次标识核对接纳情况，在会话空闲后合并检查。浏览历史、审批、待发项以及仅在 CLI 等其他客户端提交的输入都不会触发跟进。打开会话、连接重建和开启设置本身均不补跑旧轮次。

首次拟题单独处理。后续按会话每累计两个含 DSH 网页正文且已经结束的轮次检查一次。同一轮次中的多条网页消息或插话合计为一轮。如果这两轮新增的网页正文合计只有十个字符或更少，忽略空白和标点后计数，本次跳过模型请求。这些短消息仍可以作为后续检查的上下文。每个会话一次只运行一个拟题任务。关闭开关后取消后续更新任务，变更拟题模型后作废此前模型尚未写回的结果。

从最近少量轮次中提取用户正文，将当前标题一并提供给模型。让模型识别当前用户的主要任务，时间顺序只提供上下文。推进指令、局部纠偏或补充约束通常保留原标题，明确转向新目标的插话可以采纳。模型一次给出新标题或保留结果。输入按字节限长并保留完整字符，只传用户正文和原标题。附件内容、助手回复和工具输出留在原会话中。

## 生命周期与写回

用同一个 App Server 创建标记为 `thread_title` 的只读临时会话，关闭工具、MCP 和环境接入。通过结构化轮次获取简短单行标题或保留结果，随后解除订阅。拟题任务和主会话分别运行。 [Codex 临时会话逻辑](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/app/thread_title.rs#L83-L111)

记录 DSH 成功写入的自动标题。后续只更新未命名会话或仍沿用 DSH 自动标题的会话。网页手动改名与自动写回使用同一会话的串行队列，手动改名后保护该标题。其他客户端的修改以写回前的原生读回为准。App Server 当前没有原子条件写入，跨客户端同时改名仍有短暂竞态。写回前同时核对设置、历史、会话状态和标题，活动恢复或历史变化时丢弃过期结果。侧栏通过原生的标题更新通知同步名称。 [Codex 改名协议](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L799-L816)

## 验收

- 默认使用可用的 GPT‑6 Luna 和低推理强度。首次和后续均使用明确选择的模型。默认模型或所选模型不可用时跳过拟题请求，首次仍显示正文预览。
- 关掉开关、仅浏览旧会话、仅从 CLI 提交消息、标题来源不明及已有手动标题时，后续轮次不会触发自动改名。再次打开开关后从网页提交的新正文开始处理。
- 一个含网页正文的已结束轮次先等待下一轮。同轮多次插话仍计一轮。两轮新增网页正文去除空白和标点后合计不超过十个字符时跳过请求，超过十个字符且符合其余条件时只发起一次请求。
- 标题检查只使用限定范围内的用户正文。验证「继续」「打包」、局部纠偏、插话转向新主题及模型返回保留标题的行为。
- 验证连续轮次合并、重复事件去重、拟题中收到新输入、切换模型、关闭开关、手动改名或归档的情况。保留新会话首次入历史确认及原生广播刷新验收。

# 网页会话拟标题

## 设置

在「Codex on DSH」中提供「拟标题模型」和「随会话更新标题」，按 DSH Profile 保存。模型用于网页首次拟标题和开启后的标题更新。默认项为「GPT‑6 Luna（默认）」，适用于通过 ChatGPT 登录且目录提供 `gpt-6-luna` 的 OpenAI 会话。菜单与新会话默认模型共用 Codex 当前配置的提供商目录，已经保存的模型继续按原提供商标识解析。所选模型不可用或请求失败时，未命名会话显示 Codex 正文预览，已有标题继续显示当前名称。自动更新默认关闭。 [GPT‑6 Luna 模型说明](https://developers.openai.com/api/docs/models/gpt-6-luna)

设置页说明拟标题根据少量用户发言在后台单独请求所选模型。即使最后保留原标题，请求也可能增加订阅用量或 API 费用。模型的提供商与主会话可不同，发言由所选提供商处理。

### 思考强度

拟标题模型与思考强度放在「Codex on DSH」的同一条原生设置行。下拉按钮显示当前模型和强度，菜单沿用 DSH 输入栏的「模型」和「思考强度」两级结构，通过原生子菜单提供候选项。模型和强度共用一段设置说明，费用提示单独占一行。模型及强度选择后自动应用到当前 DSH Profile。

档位来自所选模型的 Codex 目录。「默认」标出实际发送的档位。OpenAI 的 GPT‑6 Luna 优先使用 Low，其他模型使用目录声明的默认档位。目录未给出可用默认档位时使用第一个可选档位，未提供任何档位时省略强度参数。使用默认模型项时也可以为 Luna 单独指定档位，仍沿用现有的 ChatGPT 登录条件。切换模型时回到新模型的默认强度。已保存的档位若从目录移除，则回到菜单显示的默认档位。

首次拟标题和后续更新共用这项强度设置。Host 用模型目录核对所选档位，并将与设置页解析一致的档位传给 Codex App Server 的拟标题轮次。强度变化后，沿用切换模型时的取消机制，避免旧结果写回。验收覆盖同一行的菜单交互、默认及显式强度传参、切换模型、无档位的模型和 Profile 重开后的读回。

## 首次拟标题与后续更新

网页提交新会话首条含文字的消息后，Host 通过原生消息标识确认该消息已进入历史，再为尚未命名的会话拟标题。纯图片、待发消息和重复提交沿用原生预览及现有去重规则。浏览器切换页面后，已开始的任务仍可完成。

开启更新后，DSH 网页中提交的用户正文才触发会话跟进，包括普通发送、领到正文的队列轮次、插话和编辑后重发。Host 用原生消息或轮次标识核对接纳情况，在会话空闲后合并检查。浏览历史、审批、待发项以及仅在 CLI 等其他客户端提交的输入都不会触发跟进。打开会话、连接重建和开启设置本身均不补跑旧轮次。

首次拟标题单独处理。后续按会话每累计两个含 DSH 网页正文且已经结束的轮次检查一次。同一轮次中的多条网页消息或插话合计为一轮。如果这两轮新增的网页正文合计只有十个字符或更少，忽略空白和标点后计数，本次跳过模型请求。这些短消息仍可以作为后续检查的上下文。每个会话一次只运行一个拟标题任务。关闭开关后取消后续更新任务，变更拟标题模型或思考强度后作废尚未写回的结果。

从最近少量轮次中提取用户正文，将当前标题一并提供给模型。让模型识别当前用户的主要任务，时间顺序只提供上下文。推进指令、局部纠偏或补充约束通常保留原标题，明确转向新目标的插话可以采纳。模型一次给出新标题或保留结果。输入按字节限长并保留完整字符，只传用户正文和原标题。附件内容、助手回复和工具输出留在原会话中。

## 生命周期与写回

用同一个 App Server 创建标记为 `thread_title` 的只读临时会话，关闭工具、MCP 和环境接入。通过结构化轮次获取简短单行标题或保留结果，随后解除订阅。拟标题任务和主会话分别运行。 [Codex 临时会话逻辑](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/tui/src/app/thread_title.rs#L83-L111)

记录 DSH 成功写入的自动标题。后续只更新未命名会话或仍沿用 DSH 自动标题的会话。网页手动改名与自动写回使用同一会话的串行队列，手动改名后保护该标题。其他客户端的修改以写回前的原生读回为准。App Server 当前没有原子条件写入，跨客户端同时改名仍有短暂竞态。写回前同时核对设置、历史、会话状态和标题，活动恢复或历史变化时丢弃过期结果。侧栏通过原生的标题更新通知同步名称。 [Codex 改名协议](https://github.com/openai/codex/blob/rust-v0.172.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L799-L816)

## 后续拟标题请求的历史注记

「Codex on DSH」提供默认关闭的「在会话历史中显示标题更新」开关，切换后自动应用。此开关只控制当前 Profile 的展示，关闭时仍正常记录请求，重新开启后显示已经记录的注记。

每次后续拟标题即将向 App Server 发送 `turn/start` 时，Host 先用现有 DSH Profile 自动标题存储保存一条「结果待确认」注记，再发出请求。注记写入失败时跳过这次请求。命中短输入过滤、模型不可用等在发送前跳过的检查不写注记。触发轮次取该批次最近一个参与计数的网页轮次。

每条注记按会话 ID 归属，只保存触发轮次 ID 和请求结果。确实写回新名字时再保存改名前后的标题。DSH 在原生轮次尾部显示「已更新标题」或「保留标题」。展开「已更新标题」可查看「旧标题 → 新标题」，长标题随可用宽度换行。待确认或未应用的注记显示「标题自动更新」及相应状态。模型返回保留或给出同名记作保留原标题。请求失败、取消或结果过期记作未应用。Host 中途退出时保留待确认状态。界面标明这是独立的拟标题请求，待确认表示请求或结果仍未核实。实际 Token 用量以模型服务的计量为准。

网页打开、重连和加载更早轮次时按原生轮次 ID 关联注记，在线时同步已保存的变动。注记仅属于 DSH 的显示数据，消息与轮次、分页游标和模型上下文均由 Codex 提供。回退后按原生轮次的可见性显示，分支按自己的会话 ID 查询。手动改名只取消自动管理资格，已经记录的拟标题请求仍可查看。

验证每次后续拟标题请求恰好新增一条注记，覆盖改名、保留、失败、取消以及存储不可写时跳过请求。首次拟标题、手动改名和发送前跳过的检查沿用当前行为。刷新以及加载更早历史后仍可定位同一条注记。回退或创建分支时只显示当前会话仍存在的相关轮次注记。已有自动标题记录能够继续参与后续更新。

## 验收

- 默认使用可用的 GPT‑6 Luna 和低推理强度。首次和后续均使用明确选择的模型。默认模型或所选模型不可用时跳过拟标题请求，首次仍显示正文预览。
- 关掉开关、仅浏览旧会话、仅从 CLI 提交消息、标题来源不明及已有手动标题时，后续轮次不会触发自动改名。再次打开开关后从网页提交的新正文开始处理。
- 一个含网页正文的已结束轮次先等待下一轮。同轮多次插话仍计一轮。两轮新增网页正文去除空白和标点后合计不超过十个字符时跳过请求，超过十个字符且符合其余条件时只发起一次请求。
- 标题检查只使用限定范围内的用户正文。验证「继续」「打包」、局部纠偏、插话转向新主题及模型返回保留标题的行为。
- 验证连续轮次合并、重复事件去重、拟标题中收到新输入、切换模型、关闭开关、手动改名或归档的情况。保留新会话首次入历史确认及原生广播刷新验收。

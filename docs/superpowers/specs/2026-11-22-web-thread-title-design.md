# 网页会话自动拟标题

网页发送新会话的首条消息后，侧栏先显示 Codex 原生预览。首条消息含有非空正文并已写入原生历史时，Host 为未命名的会话后台拟标题。仅含图片的首条消息继续显示原生预览。打开、刷新或继续已有历史的会话只读取现有标题和预览。

Host 在普通发送与继续队列流程中使用原生消息标识确认首条消息已接纳为历史条目，并复用按会话协调提交的逻辑。排队期间沿用当前预览。删除待发项即结束对该项的拟标题资格。同一会话的并行提交和重复确认合并为一次拟标题任务，任务在浏览器切换页面后仍可完成，随 Host 停止而取消。

## Codex 调用

沿用 Codex TUI 的做法。Host 在现有 App Server 上调用 `thread/start`，创建标记为 `thread_title` 的临时会话。临时会话使用只读权限，关闭工具、MCP 和环境接入。Host 发送截取自首条消息的正文，通过带 `outputSchema` 的 `turn/start` 获取简短的单行标题，随后解除订阅。OpenAI provider 经 ChatGPT 登录且模型目录提供 `gpt-5.6-luna` 时使用该模型和 `low` 推理强度，其他情况使用原会话的 provider 和模型。 [Codex TUI 标题逻辑](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/tui/src/app/thread_title.rs#L60-L118) · [Codex 临时会话逻辑](https://github.com/openai/codex/blob/rust-v0.170.0/codex-rs/tui/src/temporary_structured_request.rs)

推理成功后，Host 用 `thread/name/set` 写回原会话。推理失败、超时或结果无效时，采用首条消息正文的简短单行摘录。写回前重新读取原会话和触发消息，只有会话仍未命名、未归档且原消息仍是首条消息时才保存。同一 Host 的手动改名和自动标题写回串行处理。其他客户端的标题以写回前最后一次原生读取为准，当前 RPC 没有原子条件写入。侧栏依赖已有的名称更新通知刷新。推理与标题写回均独立于主对话的发送结果。

## 验收

覆盖首条文本消息成功生成并保存标题、重复提交只生成一次、还在排队时不启动拟标题、纯图片与旧会话沿用原生预览、推理失败使用摘录，以及生成中手动改名或首条消息变化时保留最新状态。验证临时轮次的请求与主对话使用不同会话 ID，原生改名事件能更新网页标题。

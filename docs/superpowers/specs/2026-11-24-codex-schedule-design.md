# Codex 会话定时任务设计

在 DSH Web 的 Codex 模式启用「自动化任务」。首版支持已有 Codex 会话，可创建、查看、编辑、暂停、恢复、立即投递和删除计划。DSH Host 负责时间规则、计划存储和投递回执。Codex App Server 接收消息，由原生队列和权限策略运行轮次。

## 插件与模式

以 `dsh-schedule-for-codex` 为名在本仓库维护完整的 Host 和界面源码，构建直接编译这份源码。上游发行版本、源码目录和升级流程由 fork 的维护文档记录。共存时，原生 DSH 继续使用官方插件、存储和接口。Codex 版使用独立的任务域、管理路由和页面状态；页面沿用官方表单、列表、详情和历史。模式切换只影响页面，两个后台服务在线时，已保存的 Codex 计划继续执行。

## 投递

目标只能是已有、未归档且可接收输入的 Codex 会话。创建时只读校验，投递时复查并按需恢复。任务与普通输入共用 Host 的线程提交顺序，消息交给 Codex 原生队列。投递回执表示 Codex 已接纳，结果在会话中查看。

写入 Codex 前持久保存投递标识。断线或重启后先读回原生队列和会话历史；不确定结果期间保留投递标识，避免产生第二条消息。重复任务沿用官方推算和停机补发规则，各任务独立确认。同一任务已有消息仍在队列或轮次中时，后续到期时点合并等待。

## 验收

- 通过 Codex 页首版表单创建和管理任务，检查等待期间切回 DSH 或关闭浏览器后仍能投递。
- 检查空闲、正在执行和未加载会话，验证归档校验、接纳后的回执和断线恢复。
- 检查两种模式的目录、编辑和清理操作各自读写独立任务，原生 DSH 插件继续服务旧计划。

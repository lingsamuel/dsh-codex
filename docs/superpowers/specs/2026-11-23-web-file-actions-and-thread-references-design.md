# 网页文件操作设计与 Codex 会话引用验证

## 范围

Codex 网页增加本地图片悬停和 Markdown 内嵌预览，以及右键复制图片和下载原文件。`@` 会话引用以现有 Codex 工具能否读取原会话为前提。桌面文件操作三项继续留在桌面版待办，压缩摘要独立评估。

## 本地图片预览

Codex Profile 单独挂载 DSH 原生 `SessionMediaReferences`，由现有构建流程编译 DSH 随包提供的实现。Host 从当前 Profile 的 Loader 取得文件系统模块，使原版媒体组件能识别同一个文件服务抛出的错误类型。浏览器继续使用原生悬停卡片与 Markdown 渲染器，覆盖聊天和右侧 Markdown 文档里的本地图片。媒体接口复用同源鉴权、Host 文件服务、文件大小限制、版本化缓存和内容类型响应。路径访问采用原版 DSH 的绝对路径语义，包括 Host 可读的工作区外临时文件。

## 网页原文件菜单

接入 DSH 原生 `ui-file-actions`。文件树、聊天文件链接和可用的图片预览入口显示各自适用的「复制图片」「下载原文件」操作。原文件读取复用 `workspaceFiles` 和浏览器的剪贴板及下载能力。发布的 Profile 和旧源码启动 Profile 使用同一个原版插件条目。

## Codex 会话引用验证

Codex TUI 在发送时保存线程引用，再通过 `read_thread` 按轮次读取原会话。使用现有网页配置在 App Server 0.171.0 创建临时线程后，检查其原生工具清单，未发现 `read_thread`。同一 App Server 的只读 RPC 能读取原会话的元数据和轮次。根据确认的范围，跨会话引用暂缓。

## 验收

- 打开已保存的两条历史截图链接，分别验证悬停和点击。验证聊天及右侧 Markdown 文档能显示本地图片，文件更新后能取到新版，未登录的请求无法读取。
- 验证网页菜单复制原图和下载原文件。检查新 Profile 和旧源码启动 Profile 的入口都能加载。

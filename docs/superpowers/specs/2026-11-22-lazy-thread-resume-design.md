# Codex 会话按需恢复设计

旧会话打开后，可直接输入草稿、选择模型、打开历史消息编辑器或删除确认框。DSH 移除输入框上的「点击继续会话」。前端保留 Codex 返回的实际状态，按操作所需的条件启用控件。浏览历史和准备操作期间保持原有读取方式。

| 操作 | 运行时要求与提交时机 |
| --- | --- |
| 普通发送、提交异步问答 | 原生队列可接收未加载会话的消息。为让 Codex 有机会开始执行，在明确提交时按需恢复并入队。保留原生队列的排序和暂停状态。 |
| 继续队列 | 提交时按需恢复，然后启动对应队列项。原生调用也可指定某条待发消息。若恢复已触发领取，沿用该条消息的原生 ID 核对，避免重复启动。 |
| 保存模型和推理强度 | 原生 `thread/settings/update` 需要运行时。已加载会话在选择时保存。未加载会话的选择在当前网页中按会话随草稿暂存，提交普通消息或编辑后重发时先应用设置，再提交消息。打开选择器只读取目录和会话设置。 |
| 编辑旧消息并重发、删除本轮及后续对话 | 原生 `thread/revert` 要求已加载的分页会话。提交编辑或确认删除后，先校验当前记录再按需恢复，随后重新检查历史头与空闲状态。回退成功后按原流程重发；重发失败保留草稿并报告回退结果。 |
| 插话、将待发消息改为插话、停止 | 需要真实存在的活动轮次和对应 ID。普通发送沿用现有的轮次过期后排队行为；停止和显式队列插话在目标失效时报告状态变化。 |
| 实时问答、审批、`/ps` | 只操作现有运行时。实时问答沿用等待期间订阅和原请求 ID。审批继续由 CLI 处理。`/ps` 仅查询已加载会话的后台终端。 |
| 历史、搜索、`/status`、`/goal`、改名、置顶、读回执、归档、取消归档、删除整条会话、分支 | 通过原生存储或相应 API 处理。分支由 Codex 创建新线程，源会话无需恢复。 |
| 查看、编辑、移除待发消息 | 直接操作原生队列记录，保持目标会话原有加载状态。 |

冷恢复可能自动领取已保存且未暂停的待发消息。当前队列列表只返回消息项，无法区分队列是否暂停。历史回退提交遇到已有待发消息的未加载会话，先提示处理队列。恢复后发现线程已运行或历史已变化时退出回退流程。 [Codex 回退协议](https://learn.chatgpt.com/docs/app-server#revert-thread-history) [Codex 冷恢复队列测试](https://github.com/openai/codex/blob/a29c7b97e88367044ae84c28c85451ec3e72af9f/codex-rs/app-server/tests/suite/v2/thread_queue.rs#L430-L555)

Host 在收到提交后读取最新状态，同一请求内执行必要的 `thread/resume` 和后续操作。已加载线程直接使用现有运行时。归档及权限限制以原生状态为准。恢复或设置未确认时保留草稿，发送成功以 Codex 的接纳和回显为准。

验收覆盖打开历史和准备操作期间的 RPC、首次发送和答复、待发队列继续、冷会话的模型选择、回退前历史变化、恢复失败时的草稿，以及 CLI 已在运行时的插话与停止。

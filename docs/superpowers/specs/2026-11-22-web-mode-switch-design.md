# DSH Web 双入口与 Codex 独占设计草案

在同一个 `dsh web` 实例中，两个标签页可以分别使用原生 DSH 和 Codex。两个入口共用 Web profile、服务地址和登录状态。用户通过官方插件页安装 DSH ChatGPT，入口装配由插件管理。

## 共存设置、侧栏开关与 Codex 独占

- DSH ChatGPT 的插件设置提供「允许标签页使用不同模式」和「Codex 独占」两个原生设置开关。共存默认开启，独占默认关闭。设置按当前 Web profile 保存，Web 重启后保留。DSH 和 Codex 均可访问插件设置。
- 共存开启时，侧栏「启用 Codex 模式」显示当前标签页所用模式。点击后立即切换当前页，同时改变之后打开且省略 `mode` 的入口默认值。其他已打开的标签页继续使用各自入口。显式指定 `?mode=dsh` 或 `?mode=codex` 时按地址打开，复制已有标签页时沿用其中的模式。默认入口初始为 DSH。
- 共存关闭时，按保存的默认值统一整个实例为 DSH 或 Codex。打开或刷新入口时，以实例当前模式为准。侧栏点击后对整个实例应用热切换。旧模式的标签页停止提交操作，并提示重新加载到当前模式。重新开启共存后，可再次按标签页与 URL 选择入口。
- 侧栏开关置于「插件」等入口下方、工作区标题及列表上方。沿用 DSH 侧栏行和原生 `Switch` 的交互与样式。侧栏收起时遵循原生窄栏的呈现约定。
- 打开独占时，Host 检查整个 profile 的 DSH 运行与等待状态，通过现有热切换流程进入 Codex 独占。切换和保存成功后，发起页进入 Codex，打开或刷新其他入口也进入 Codex，并隐藏侧栏开关。已打开的 DSH 页提示当前实例已切换，导航或刷新后进入 Codex。取消或失败时恢复并显示先前状态。
- 独占期间统一使用 Codex。关闭独占后恢复先前的共存设置和默认值。共存开启时，发起页保留 Codex 会话，省略 `mode` 的新入口采用保存的默认值。共存关闭时，整个实例回到保存的模式。遇到装配中间状态时，从现有恢复页恢复 DSH 并退出独占。

## Host 与浏览器装配

共存模式复用 `experiment/web-dual-entry` 的双入口装配。Host 保留 DSH 会话服务，并挂载独立的 Codex API。两个浏览器入口各自加载会话和工作区控制器。原生文件服务按明确的会话来源确定工作目录，Codex 上传使用独立路由，两个入口沿用各自的文件和附件操作。原生 DSH 页继续使用官方插件热更新，Codex 页在打开和刷新时按本页入口加载插件装配。

关闭共存后以及独占期间，实例使用 `feat/web-mode-switch` 的两阶段热切换及同源过渡页。Host 先释放与目标装配冲突的服务，再启用目标装配。官方 Web、认证、插件管理器和用户配置层参与各模式的装配。以当前项目使用的 DSH 0.2.3-alpha.2 验收。

由有权管理当前 profile 的用户修改模式设置。共存开启时，修改默认模式只保存入口偏好。需要变更装配时，Host 串行处理装配与设置保存，浏览器以 Host 返回的实际状态为准。任一阶段应用或保存失败时，按相反顺序恢复切换前的组合。进程重启或回滚失败留下中间状态时，从同源恢复页返回 Web 首页。

## 品牌切换动画

侧栏开关和展开侧栏的黑色徽标共用切换操作。徽标点击由插件处理，品牌区其他部分继续沿用 DSH 的「新建会话」。独占期间徽标仅作标识。切换失败时，品牌保持原模式并沿用现有反馈。

Host 确认目标状态后，徽标绕竖轴转一圈，侧转时更换 `Harness` 与 `on DSH`，同一节拍让 DeepSeek 与 Codex 的字标、图标淡入淡出。工作区和编辑器允许退出，由原来的页面装配在目标模式恢复。支持同源文档过渡的浏览器用短淡入淡出衔接新页。开启系统减少动态效果时直接切换。

切换开始时，侧栏里的插件入口、开关、工作区等一起退场，单独保留品牌和侧栏底色。主工作区的 HARNESS 和旋转圆圈贯穿跨页交接，位置与样式固定，只有提示文字依实际阶段更新。检测到会话载入状态时才显示「正在载入会话」。目标页面先于 DSH 启动脚本绘制交接画面，待新布局位置稳定后交回页面。普通刷新显示 DSH 原生启动状态，加载失败时恢复原生诊断界面。

## 会话与草稿

- 两种入口各自读写原生会话记录、当前会话和草稿，已提交的任务由各自的后端运行。整实例切换会离开发起页。仅存于该页的编辑、附件和模型选择，用户确认放弃后才离开。提交进行中时提示等待。
- 目标装配需要释放 DSH 会话服务时，如果任一 DSH 会话仍在运行或等待交互，保留当前设置与装配并提示先处理。整实例切换期间的在途写请求、并发操作和失败恢复沿用现有流程。

## 验收

- 在同一个 Web 进程的两个标签页分别打开 DSH 和 Codex，验证共用登录态、并行发送、历史、上传和文件预览，确认当前会话及草稿分别在刷新后恢复。
- 验证侧栏开关在「插件」等入口下方、工作区上方且键盘可操作。双向切换时，确认发起页立即进入目标模式、省略 `mode` 的新标签页采用新默认值、其他已打开的标签页刷新后保留入口、显式指定 `mode` 的新标签页按指定模式打开。覆盖未提交编辑、附件和在途提交。
- 验证新 profile 默认允许共存。分别以 DSH 和 Codex 为默认值关闭共存，核对现有及新开标签页统一、相反的 URL 参数按实例模式打开、侧栏可切换整个实例、重启后仍为单模式，并验证重新开启共存。
- 在共存开启和关闭时分别启用独占，验证各入口只进入 Codex、重启后仍生效、插件设置可访问且侧栏模式开关隐藏。关闭独占后核对恢复的共存状态、默认值和当前会话。
- 验证有活动 DSH 会话时暂缓释放 DSH 服务，以及并发切换、第二阶段失败回滚和中间状态的一键恢复。用临时目录验收插件安装和卸载，验证独立 Codex profile 的现有入口。

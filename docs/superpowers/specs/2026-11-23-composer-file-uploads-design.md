# 对话输入栏文件上传设计

## 交互

网页用户可以通过输入栏「+ → 文件」选择普通文件，也可以把普通文件拖入输入栏。拖放和文件选择都上传原始字节。工作区已有的文件和目录可以通过 `@` 引用。

复用 DSH 原生附件栏显示文件名、上传进度和错误，并提供移除和重试。支持单独发送文件，也支持文件、正文和图片一起发送。附件上传完成后可随消息发送、排队或插话。队列和已发送消息显示文件名并提供下载，编辑消息正文时保留原有附件。

## 保存和提交

浏览器通过 DSH 已认证的同源接口流式上传文件。Host 使用 DSH 原生附件存储 `saveFileStream` 保存原始字节，并返回关联当前草稿会话的上传回执。上传中途失败时通过原生存储流程清理未完成的临时文件。浏览器重试消息提交时可复用已经完成的上传。

DSH 附件仓库按 SHA-256 保存文件内容。内容相同的上传复用同一个磁盘对象，保留文件名的路径通过硬链接指向该对象。后续对本地原文件的修改、移动或删除不影响已上传的数据。原文件内容变化后再次上传会得到新对象，旧消息继续引用旧版本。保存在 DSH 附件仓库中的对象可以跨 Host 重启使用。

提交消息时，Host 核对上传回执，由附件存储解析供 Codex 读取的 Host 路径。把正文和路径引用随 Codex 原生文本输入提交，并使用原生文本元素标出文件引用的范围，供网页从队列和历史还原附件。Codex 仍按会话权限读取文件。队列、历史和会话分支保存附件引用，文件字节存放在 DSH 附件仓库。

上传和提交沿用 DSH 的访问授权。下载从当前会话的附件引用定位文件，通过同源接口读取；路径由 Host 从受管附件引用解析。移除草稿附件、取消待发项或删除会话只移除对应引用，受管对象沿用 DSH 附件仓库的保留规则。

## 验收

- 从普通浏览器选择和拖入普通文件，验证上传进度、错误重试、移除、纯附件发送和图文混合发送。
- 两次上传同一内容，包括使用不同文件名，核对它们共用一个存储对象。修改或删除原文件后，仍能从历史下载第一次上传的字节。再次上传修改后的内容，分别检查新旧消息指向的版本。
- 在 Codex 原生队列和历史中检查附件引用。验证首条消息、排队、插话、编辑重发、分支和 Host 重启后可以读取已保存的文件，消息提交失败后可以重试。
- 验证未通过授权的请求无法上传或下载，并检查原有图片粘贴、普通文本发送和 `@` 路径引用。

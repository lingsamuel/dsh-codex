# Codex 网页跨会话引用设计

## 使用方式

在输入栏输入 `@` 时，DSH 原生候选菜单同时提供文件和 Codex 历史会话。会话候选来自同一 App Server，优先显示当前工作目录内的匹配，并排除当前线程、临时线程和归档线程。选中后在输入栏显示会话标题，提交时保存原生 `thread://` 引用和对应的原生文本元素。草稿、队列、插话和已发送消息保留引用身份，标题变化后仍能定位到同一线程。

模型使用引用时调用 `read_thread`，按轮次读取原会话当前已保存的正文和必要元数据。工具使用已有的 Codex 历史分页逻辑，返回有界的结果。被引用的内容以历史资料交给模型，回答仍落在当前会话。

## 工具的归属

官方 `codex_tui` 是 CLI 进程启动的本机 MCP，地址和访问凭据随进程生成。目标会话已经连接该服务时，DSH 沿用它的 `read_thread`。DSH 接入的服务使用独立的 MCP 名称。

DSH 从会话创建或冷恢复请求传入线程级 MCP 配置。Codex App Server 通过标准输入输出启动会话工具进程，并负责它的生命周期。工具进程直接通过同一个 App Server 执行已选的会话操作。DSH Host 和网页可以独立关闭。

新建网页会话在创建时带上线程级配置，供后续轮次使用。对已有会话，优先沿用已确认可调用的原生 `read_thread`。如果已有会话需要按当前提交流程冷恢复，可在该次恢复时接入。已经加载且没有读取工具的会话会提示当前不可用，并保留引用和草稿。工具就绪检查跟随显式操作，浏览历史仍走现有只读流程。

## 会话工具

对齐原版 `codex_tui` 的九项任务操作。除读取外，还包括列出会话、列出归档会话、等待其他会话、新建、分支、发送消息、改名及归档或恢复。新建、分支和跨会话发送沿用原版的工具审批方式。托管工作树作为独立功能处理。

## 验收

- 验证新建网页会话能搜索并引用旧会话，模型按需读取已落盘轮次，原生队列和历史显示引用。验证同一消息内的 `@` 文件引用、附件和会话引用可一起使用。
- 在独立测试会话中关闭创建连接及 DSH Host，验证已加载线程的工具仍由 Codex 托管。按现有关闭和恢复路径验证旧线程的工具归属及续用情况。
- 验证原版九项工具的参数、调用结果及涉及委派的原生审批。等待类调用应支持取消。
- 覆盖 CLI 已有工具、网页新建、可冷恢复和已加载但无工具四种情形。已有会话在工具暂不可用时应显示原因并保留草稿和其他发送能力。

## 可行性验证

在本机 App Server 0.171.0 的临时会话中，通过线程级配置启动标准输入输出 MCP。关闭创建连接后，另一个连接仍能调用 `read_thread`，读取真实旧会话的一页历史。在隔离的 App Server 中重启服务后，也验证了持久化会话能保留原线程 ID 冷恢复，并在同一次请求中接入工具。模型端调用纳入实现验收。

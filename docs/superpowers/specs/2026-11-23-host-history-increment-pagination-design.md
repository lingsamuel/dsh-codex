# Host 历史增量分页与发送背压

## 范围

实时增量按原生页读取和发送。同一轮次连跨多页时，Host 在交付当前页之前不会读取下一页，也不会把多页正文编码为一个 SSE 帧。首屏和回退替换快照、手动加载旧页、会话导出及 DSH 图片缓存按各自流程处理。

## 分页和发送

- 将已有原生分页循环提取为可等待的迭代入口，共用不透明游标和重复游标检测。有完整结果需求的调用方继续使用原有的收集方法。实时尾部逐页处理普通轮次、轮内条目和晚到条目。
- 沿用现有 `change` 帧。每页按条目分批，普通帧的 UTF-8 编码预算为 2 MiB，包含 SSE 和 JSON 包装。单条记录超过预算时独占一帧，沿用 64 KiB 网络分块发送。保留可读取的完整原生条目。
- 等待当前页的所有增量帧交给 HTTP 层后才继续原生分页。分页版读取轮次元数据和条目页，旧版沿用原生整轮响应并对发送内容分批。单条原生记录和单次原生 RPC 响应的体积由上游决定。

## 顺序和恢复

- 同一轮次按原生顺序送达。新确认的终态、结束时间和错误在该轮相关条目之后发布。较早轮次的晚到条目继续携带 `onlyIfLoaded`，按原生条目 ID 合并。
- 扫描普通轮次前获取线程级条目游标上界，普通增量先发，随后逐页补发未由普通扫描覆盖的晚到条目。检查点最多推进到本轮开始时取得的上界。扫描期间新增的条目由后续检查补齐。
- 历史检查点和对应阅读回执排在整批历史之后。回退使游标失效时停止发后续增量，并按现有流程发送权威替换快照。连接中断或增量未读完时保留原检查点，浏览器重连后可重放。

## 验收

- 使用同一轮次的四页历史，每页包含一条约 3 MiB 的记录。暂停消费首帧后，Host 只请求第一页。继续读取后四条记录按顺序送达，每个编码帧至多包含一条大记录。
- 用单页多条多字节记录验证 UTF-8 帧预算。验证终态和阅读回执在对应条目之后，检查点在所有页之后。中途断开时验证上次检查点可用于重放。
- 覆盖晚到条目、分页期间并发追加、回退替换、重复游标，以及现有的旧版历史跟随路径。

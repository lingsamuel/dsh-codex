# Codex 右侧栏交互式终端

## 行为

- 共存版和极简版的 Codex 页面都提供 DSH 原有的「新建终端」入口、shell 选择、快捷键和终端标签页。已创建的 Codex 线程和未发送的网页草稿都可以打开终端。读取已创建线程的目录无需将线程加载到 Codex 的运行时。
- 已创建线程以 Codex 返回的当前工作目录为准。网页草稿以输入栏当前选择为准，默认使用草稿的本地目录，选中已有 Worktree 时使用该检出对应的项目目录。选中「新建工作树」后，首次打开终端会从所选基准创建检出，首条消息复用同一个 Worktree。打开终端无需发送消息或提前创建 Codex 线程。
- 更改工作目录选择后，新终端使用新目录，已有 shell 保留启动目录。目录失效或 Git 创建失败时显示错误。草稿发送成功并切换到真实线程后，原有终端标签和进程随会话接续。首发失败或草稿仍保留时，终端继续归属于草稿。
- 折叠右侧栏、切换会话和刷新页面遵循 DSH 原有的终端保留及重连规则。关闭终端标签页由 DSH 控制器结束对应进程。DSH Codex 的 Host 插件卸载时释放其拥有的终端进程。
- 交互式 shell 由 DSH Host 以运行 Host 的系统用户权限启动，沿用官方用户终端的认证和权限模型。Codex 的 `/ps` 和会话面板继续处理由 Codex Agent 启动的后台进程。

## 接入

复用官方右侧栏终端、浏览器终端模型、Typert Gateway 和 Host 终端控制器。浏览器用当前会话 ID 调用 Codex 终端入口。Host 将请求绑定到有来源标识的终端所有者，只有认证后的 DSH owner 可以操作。创建 shell 时，已创建线程通过 `thread/read` 解析目录，草稿使用现有草稿 ID、目录和 Git 选择。Host 校验本地目录，沿用首发流程的 Worktree 选择校验和检出逻辑。终端 ID、输入和尺寸继续由官方控制器校验。

打开终端和首发共用 Worktree 选择 ID，同一选择的检出解析串行化，并发或失败重试复用已经创建的检出。已用于打开终端的选择随草稿持久化，刷新后继续用于首发。更换选择时保留先前创建的检出及其中可能存在的修改。仅在草稿完成首发交接时关联原生线程 ID，并用原有终端 ID 接续标签，避免重复启动 shell。进程随 Host 生命周期管理。

两种 Web Profile 都加载官方终端模块，共存版遵循 Profile 已启用的插件清单。Codex 页将官方客户端模型的终端请求导入 Codex 终端入口。原生 DSH 页继续用自己的 Typert 路由。极简版沿用 Profile 的共享执行服务和 Codex 已提供的会话目录。

Codex App Server 的 `command/exec` 支持交互式 PTY，但其进程绑定 RPC 连接。接到这一路径需要另外维护 Host 连接、屏幕恢复和终端回收。复用 DSH 的执行及终端控制器能沿用现有行为，改动集中在线程归属、工作目录和模式接线。

## 验收

- 在共存版和极简版用右侧栏打开真实 shell。运行 `pwd`，核对结果来自当前线程。切换到另一工作目录后再次打开，验证旧终端保留原目录。
- 用未发送草稿分别验证本地目录、已有 Worktree 和所选基准的新建 Worktree。并发打开终端和发送首条消息时只创建一次检出，刷新后重试继续复用。首发成功后原有进程和屏幕接续到真实线程，首发失败时能在草稿中继续使用终端。
- 验证交互输入、输出、调整尺寸、刷新重连和关闭清理。跨会话访问终端失败，失效目录及非 owner 请求都不会分配进程。
- 在同一共存实例中切换到原生 DSH，确认终端仍按原生会话启动。验证启动和热更新后的模块装配，以及保留旧配置的极简 Profile。

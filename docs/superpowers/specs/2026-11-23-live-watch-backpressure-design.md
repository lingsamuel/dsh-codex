# 浏览器实时同步背压

## 范围

第一阶段解决浏览器在历史投影、图片解码或补读过程中持续解析新 SSE 帧的问题。会话与目录沿用同源 `/api/codex/watch` 和现有 SSE 帧格式，共用 Fetch 流读取逻辑。Host 历史增量分页独立交付。首屏快照分批另行评估。DSH 图片展示缓存已记录为上游待办。

## 读取和续读

- 请求使用 `cache: 'no-store'`，Host 保留现有的 `Cache-Control: no-store`。复用 SSE 流解析器处理跨网络块的 UTF-8、心跳和检查点。浏览器逐帧等待应用处理，当前帧处理完成后才解析下一帧的 JSON。
- 只有前序帧成功投影后，历史检查点才写入续读游标。投影失败时保留上一个成功应用的检查点，并按现有的尾部快照与增量合并逻辑恢复。切换会话、释放观察引用或关闭页面时取消读取，过期连接的检查点不得推进游标。
- 维持现有的断开提示、首次 HTTP 历史补读和目录刷新。新连接的历史快照合并后收起提示。等待网络数据时检测连接停更，正在处理上一帧的时间不计入网络空闲。每个观察器同时只建立一条连接，断开后沿用 3 秒重试间隔。

## 验收

- 暂停一帧的投影，验证后续数据帧和检查点都等待。恢复后按顺序应用，重新连接携带最后成功应用的检查点。
- 断开、主动取消和投影失败时验证资源释放，并确认重连补齐历史、目录刷新和会话切换行为。
- 使用 Chromium 和 DSH HTTP 桥验证慢投影时的应用队列及网络拉取情况。浏览器和传输层允许有限预读，单帧内容大小由后续 Host 工作处理。

# Codex 工作区和会话交互接入设计

在现有 DSH 网页的 Codex 模式中接入项目管理、文件输入、按需取消归档和网页审批。继续使用 DSH 的交互组件与 Codex 的原生项目、线程、队列和审批记录。

## 工作区管理

对已登记的 Codex 项目复用 DSH 的工作区菜单、改名弹窗和拖动排序。改名用 `project/update` 更新名称。排序用 `project/move` 更新同一项目列表中的位置。拖到目录分组区域时，目标位置为原生项目列表末尾。原生 `project/changed` 事件和项目列表负责跨客户端同步。

删除项目使用 `project/delete`。确认框说明该操作会解除会话的项目归属，会话历史和目录文件会保留。侧栏随后按各会话的工作目录重新分组。目录自动分组的标题仍取自目录名，组间顺序仍按最近活动计算。项目改名、删除和手动排序入口仅面向有 Codex 项目 ID 的分组。

## 文件和目录输入

复用 DSH 的原生 `@` 补全、路径引用标签和序列化格式。候选来自 Codex 会话工作目录中的文件和目录。引用随文本走现有发送、排队和插话流程，Codex 按需读取目标。贴图继续使用内嵌图片流程。

## 按需取消归档

归档会话允许阅读和编辑草稿。发送按钮显示「取消归档并发送」。提交时 Host 在现有按线程串行的操作中确认原生归档状态，依次执行必要的 `thread/unarchive`、`thread/resume`、草稿模型设置和原生消息提交。按线程 ID 查询 Codex 归档列表确认状态，避免根据 `thread/read` 的 `notLoaded` 推断。只打开、翻阅或写草稿时仍以只读方式查询。继续归档会话的待发队列也通过明确的继续操作触发取消归档，并保留原有的队首确认机制。

取消归档或恢复失败时保留草稿并报告失败步骤。取消归档已成功时，侧栏按 Codex 的最新状态显示；后续提交失败时，用户可以继续使用原草稿。

## 网页审批

在用户正在查看的 Codex 会话进入待审批状态时，沿用问答的按需订阅和原请求回复方式。通过 DSH 原生审批卡展示命令、文件变更、网络访问和额外权限请求。展示内容和决定范围取自 Codex 原始请求。仅呈现该请求允许的决定，授权范围用「本次」或「本会话」明确显示。权限请求按原生的权限响应结构提交。

网页点击决定后由 Host 通过接收请求的同一连接回复此请求。CLI 和网页可处理同一请求，接收到 `serverRequest/resolved` 时清除审批卡和等待状态。浏览其他会话继续使用现有的只读监听和侧栏提示。问答和审批同时存在时仍可从当前会话打开各自的待处理交互。

## 权限预设

输入栏使用 DSH 权限选择器，选项来自 Codex 的原生权限目录。当前会话显示 Codex 已确认的生效预设、沙箱和审批方式。缺少会话级原生设置时显示未知，已有历史值注明来自上一轮。切换只在用户选择后更新当前线程，并按需加载其运行时。完全权限沿用 DSH 的选择确认。

通用设置提供「跟随 Codex」和当前可用的 Codex 权限预设。默认值保存在此 Web profile 的运行数据中，只在此网页创建新 Codex 线程时传入。已建线程、复用草稿以及 CLI 的原生配置各自保留原来的权限。

## 验收

- 从 DSH 改名、拖动和删除原生项目，重新打开网页并从原生目录验证状态。删除后检查原会话可打开、目录文件仍可读取。验证目录自动分组和会话拖动的行为。
- 发送工作区文件、目录引用和图文混合消息。检查路径含空格时的格式、历史、排队、插话和发送失败后的草稿。
- 打开归档会话后确认仍在归档列表。发送时确认同一个线程恢复并接收一条消息。验证继续队列、其他客户端同时取消归档，以及提交失败时的保留草稿。
- 使用隔离 Codex 实例验证批准、拒绝、适用的授权范围和 CLI 抢先处理。检查旧请求结束后卡片关闭，重复点击不会再次提交。
- 对照 Codex 可选权限目录和设置确认，检查当前会话状态。改变默认值后创建新会话，并验证复用草稿和 CLI 配置。

## 归档会话的其他操作

侧栏搜索按归档筛选检索原生正文。命中的归档会话直接进入历史视图，保留归档状态。归档会话的置顶写入 Codex 原生分组，手动拖动沿用 DSH 视图顺序，二者保留归档状态。

归档会话可以打开历史编辑器和回退确认框。提交编辑或确认回退时，提示会取消归档并改写历史。Host 检查原生历史头，按需取消归档，再读取待发队列。队列为空时才恢复运行时，恢复后再次核对空闲状态和历史头。检查失败时返回具体原因，保留用户草稿。

归档会话直接在原生队列栏显示待发消息和附件。没有待发消息时收起队列栏和继续入口。查看保留归档状态和草稿，明确继续才解除归档并按需加载运行时。编辑和移除使用取消归档后的原生队列操作。

验收分别覆盖归档正文搜索、命中后查看、置顶与拖动、历史改写确认、队列非空或历史变化时的拒绝，以及查看待发队列后线程仍归档且未加载。

## 归档会话的异步问答

打开归档会话时，最新轮次里已保存且在历史中尚未作答的异步题目会出现在原生问答面板。用户可填写、修改或收起草稿。浏览和填写阶段只读取会话，归档状态和运行时都保持原样。题目和选项继续在历史中显示。

面板提交按钮写明「取消归档并提交」。选项和文本框中的 Enter 用于选择和编辑。最后一题的跳过按钮若提交前面已填的答复，也写明会取消归档并提交。Host 先检查提问仍属于适用的最新轮次，并核对历史中的答复。随后按需取消归档，读取原生队列，过滤其他客户端已经提交的答复。确有新答复时才加载原会话，复查轮次，再用原问题身份提交。问题失效时提示原因，失败的提交保留草稿。保密题继续沿用内存草稿和输入遮罩。

验收覆盖打开和填写时保持归档、提交后在原会话收到答复，以及问题过期或已有答复时的行为。

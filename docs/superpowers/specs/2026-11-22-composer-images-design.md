# 对话输入栏图片附件设计草案

## 现状

Codex 会话使用原生 DSH 输入栏，但插件禁用了 `addFiles`，因此原生粘贴入口无法接收图片。客户端和 Host 的消息提交也只接受文本。历史记录已有将 Codex 内嵌图片映射为 DSH 附件的能力。

## 交互

- 在可发送的对话输入框中直接粘贴剪贴板图片，使用 DSH 原生附件栏预览和移除。原生选择文件和拖放共用同一个图片入口。
- 可以发送纯图片、图片加文字或多张图片。忙碌时沿用原生排队和插话操作。点待发消息右侧的铅笔可行内编辑正文。纯附件消息可补写正文，清空正文也会保留图片和文件。
- 图片读取或发送失败时沿用原生错误提示和草稿保留流程。发送成功以原生队列或会话历史回显为准。

## 接入

复用 DSH 已有的内嵌图片草稿、预览和编码流程，在 Codex 输入栏接收原生支持的图片格式。图片随提交发送，由 Codex 持有待发队列和已发送历史。客户端将 DSH 图片输入转换为 Codex 原生 `image` 输入，Host 校验内嵌图片数据后沿用 `thread/queue/add` 和 `turn/steer`。通用文件、目录和远程 URL 不在本次接入范围内。

队列和对话历史使用同一套图片投影逻辑。原生回显确认后，按 DSH 的附件生命周期交接预览；队列项更新或移除时释放由它持有的图片缓存。Codex 会话通过构建补丁复用 DSH 队列组件的行内编辑，Host 沿用队列操作保存正文和原有附件。

## 验收

在浏览器中验证聚焦输入框后粘贴截图、显示预览、移除图片、发送纯图和图文混合消息。通过 Codex 协议验证排队和插话携带原始图片数据，待发文字编辑保留图片，发出后可以在对话里重新打开图片。验证发送失败后图片仍可重试，以及普通文本粘贴和发送仍可用。

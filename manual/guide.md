# 安装与使用

## 已接入功能

- **工作区与会话。** 按 Codex 项目和工作目录组织会话。支持项目管理、目录转为项目、Git 工作树选择和切换，以及会话新建与续接、改名、置顶、未读、归档、删除和排序。
- **新建会话。** 每个工作区复用自己的空白输入栏，首次发送、创建 Goal 或审查时才创建 Codex 线程。正文和附件沿用 DSH 的原生输入行为。同一个 Host 仍在运行时，首发或审查回执丢失后可在同一标签页刷新并重试原请求。若提示核对，可在输入区用「打开目标会话」查看原生记录。
- **历史与分支。** 打开会话时优先显示最近至少三轮，后台默认补齐至最近十五轮。点击「加载更早」默认再读十五轮，每读完一轮就显示，保留当前阅读位置。超大轮次先显示摘要，可继续加载本轮详情。在「设置 → Codex on DSH」可以调整首屏预算、轮数和预读开关。数字输入在按 Enter 或离开输入框时自动应用，开关切换后自动应用，下次打开会话时采用新设置。会话内搜索可以定位到更早的消息，也支持查看子智能体记录、创建分支、回退和导出 Markdown。
- **消息与任务。** 发送和插话会立即显示气泡，排队的消息显示在输入栏上方。网页实时跟随 Codex 写入的消息和工具记录。支持图片粘贴、文件上传、`@` 路径引用、审批与问答、任务清单，以及查看和停止后台进程。会话时间旁的蓝点表示仍有后台进程。
- **自动化任务。** 在侧栏打开「自动化任务」，新建计划时填写指令、选择已有的 Codex 会话并设置时间。计划可编辑、暂停、恢复、立即运行和删除。DSH Host 与 Codex App Server 在线时，关闭浏览器或切回原生 DSH 标签页后仍会触发计划。
- **文件与预览。** 从右侧栏的「文件」页浏览当前会话的工作目录，搜索文件名并打开预览。悬停在本地图片链接上可以查看缩略图。聊天和右侧栏的 Markdown 文档支持内嵌本地图片。聊天、文件树和独立图片预览的右键菜单支持下载原文件，图片还有复制操作。支持文件行号定位、轮次文件差异，以及 Codex Visualize 交互预览。
- **设置与命令。** Codex 模型、推理等级和权限预设，以及 DSH 原生界面设置。命令菜单接入 `/status`、`/ps`、`/rename`、`/compact`、`/review`、`/plan`、`/goal` 和 `/export`。
- **技能、插件与 MCP。** 支持 `$` 技能选择、Codex 插件安装与卸载、App 授权、MCP 服务与工具查看、配置重载和 OAuth 登录。打开已加载且未归档的 Codex 会话时，MCP 设置显示该会话的连接状态。新会话草稿和其他没有可用会话的场景显示全局配置。在插件详情可启用或停用 Codex 允许切换的已安装插件。开关修改 Codex 用户级配置，并保留插件安装。

## 使用细节

- **实时同步。** 当前会话同步中断时，输入区上方会提示正在重连。已加载的历史仍可查看，侧栏可继续独立更新。会话补齐后提示自动消失。
- **上传文件。** 把文件拖入输入栏，或在「+ → 文件」中选择。上传完成后可以单独发送，也可以和正文、图片一起发送。待发消息和已发送消息可以下载上传时的版本。Host 按文件内容去重，原文件之后的编辑或删除不会影响已上传的版本。
- **引用旧会话。** 输入 `@` 加标题关键词来匹配会话的显示标题。正文检索使用侧栏搜索。模型按需读取所选会话的历史，点击已发送的引用可以打开原会话。网页新建的会话由 Codex 启动会话工具。已有会话若暂时缺少读取工具，提交引用时会提示并保留草稿。

- **目录转为项目。** 同目录已有项目时会复用。已保存的普通和归档会话会迁入项目，保留历史、归档状态和工作目录。部分迁移失败时，可重试剩余会话。
- **子智能体。** 已打开的会话会实时显示新启动的子智能体。轮次的工作过程收起时，可展开查看其中的子智能体活动，点击路径即可打开其对话。Codex 允许直接输入的子会话支持发消息、插话和手动继续待发队列。
- **队列与插话。** 会话忙碌时，Enter 使用 DSH 设置中的默认发送方式，Ctrl/⌘+Enter 使用另一种。待发消息可编辑、移除或改成插话。待发项插话期间，队列保留该项的正文和附件，输入栏草稿照常保留。投递待确认时，可在队列中核对投递或下载原稿，副本保留至 Host 退出。停止当前轮次也会暂停队列，可手动继续。
- **定时投递。** 指令到期后进入目标会话的 Codex 队列。队列中已有待发消息时沿用原生顺序。投递记录确认 Codex 已接纳指令，执行进度和结果在目标会话中查看。回执无法确认时可先检查目标会话和队列，确认未送达后可以重新设置运行时间。草稿和归档会话不可作为目标。原生 DSH 模式的「自动化任务」使用自己的任务列表。
- **归档会话。** 查看历史、查看待发消息、导出和编辑草稿会保留归档状态。待发消息会在输入栏上方显示，空队列收起。发送消息、提交问答、继续队列、改名和创建分支会解除原会话的归档。编辑或移除待发消息前，需先取消归档。
- **审批与问答。** 网页和 CLI 都可处理审批和问答。提交答复时立即显示气泡。保密题的自由输入和聊天回显均使用遮罩，整组草稿保存在内存，关闭面板或刷新后清空。异步题全部跳过时只收起面板，之后可以重新打开作答。跳过部分题目时，只提交已填写的答复。异步答复优先插入提问所在的运行轮次。提问仍在最新轮次时，轮次结束或暂不能接收插话都会让答复进入队列。
- **模型与权限。** 在「设置 → Codex on DSH」选择新会话默认模型、思考强度和权限，更改立即应用于当前 DSH Profile 的新会话。「跟随 Codex」会显示 Codex 当前的默认值，继承时按会话工作目录解析配置。输入栏中明确选择的模型优先，已有会话沿用自己的设置。未加载会话的模型选择和归档会话的设置随草稿提交。默认权限用于未明确选择权限的新会话。权限菜单切换后续轮次的权限，插话沿用本轮权限。
- **分支、回退与重发。** 从指定轮次创建分支会复制该轮的完整记录。编辑旧消息和删除本轮及后续对话适用于空闲或未加载的分页会话，有待发消息或历史变化时会中止。编辑旧消息会先回退，再在原会话重发。回退保留工作区文件和已执行操作的影响。
- **删除项目或会话。** 删除项目会解除会话的项目归属，侧栏按工作目录重新分组。永久删除会话会移除该会话及其子智能体历史。两种操作都保留工作区文件。
- **自动标题。** 在「设置 → Codex on DSH」可以单独选择「拟标题模型」。新会话默认模型和拟标题模型的菜单都列出 Codex 当前配置的提供商下的模型。默认使用可用的 GPT‑6 Luna（低推理强度）。首次拟题和后续更新都使用这项设置。选定模型不可用或请求失败时，未命名会话显示正文预览，已命名会话保留原标题。
- **随会话更新标题。** 此开关默认关闭。开启后，每累计两轮含网页用户发言的对话，就可以用少量用户正文检查任务是否变化。两轮新增正文去掉空白和标点后不超过十个字符时跳过请求。同轮插话只算一轮。已手动起名的会话保留标题。拟题会向所选提供商发起额外的模型请求，即使标题没有变化，也可能增加订阅用量或 API 费用。
- **命令与计划。** `/compact` 需要有历史的空闲会话。未加载会话有待发消息时，先处理队列，再压缩或审查。单独发送 `/plan` 切换模式，也可直接发送 `/plan 任务`，按计划模式开启下一轮。通过命令菜单或模式标签切换时，等待回执期间仍可停止当前轮次。生成的计划可折叠、下载为 Markdown，或在右侧栏阅读。
- **目标。** 可从命令菜单进入 `/goal` 模式后发送，或直接发送 `/goal 目标内容`。目标气泡高亮命令，底部显示 Goal 图标。该模式下可在「+」菜单设置 token 预算，退出待提交模式会保留输入。DSH 进度条提供目标管理及 Codex 返回的用量和预算。目标达成后，对应轮次末尾显示实际用时。
- **Visualize。** 预览需要 DSH Host 能读取源文件，并能使用本机的 Python 3 和 Codex 插件缓存中的 Visualize 渲染脚本。
- **工作区链接。** 点击聊天里的工作区目录链接，右侧「文件」页会展开并定位到该目录。文件链接仍可直接打开预览。
- **技能与 MCP。** 技能按发送或插话的实际执行目录解析。网页支持处理会话中的标准 MCP 表单和授权请求，复杂表单及额外身份验证可在 CLI 完成。
- **Git 工作树。** 新工作树在首次打开终端或发送消息时从所选基准创建，位于源仓库同级目录，使用分离 HEAD。已有会话在空闲时可切换工作树并沿用原会话。未提交改动留在各自检出中。
- **交互式终端。** 展开右侧栏并选择「新建终端」。未发送的草稿会使用输入栏选中的目录或工作树。首发后已打开的 shell 随会话接续。终端以运行 DSH Host 的系统用户身份执行。
- **导出会话。** 会话标题栏的「复制会话为 Markdown」和「下载 Markdown」，以及 `/export`，都读取完整的已保存会话，保留正文、代码块、可见工具记录和附件说明。

## 安装与更新

### 选择插件包

**一般用户选 `dsh-for-codex-<版本>.tgz` 即可。** 它直接装进已有的 DSH Web。需要单独启动极简 DSH Web 服务时，选 `dsh-for-codex-min-<版本>.tgz`。

从源码打包时，在仓库根目录依次运行 `npm ci` 和 `npm run package:plugin`，一次在 `artifacts/` 生成两个 `.tgz`。也可以从 GitHub Actions 的 Build 工作流下载并解压 `dsh-for-codex` 构建产物。

两个包的 npm 名称都是 `dsh-for-codex`。每个包都包含下表的两份 YAML，且每份文件在两个包中的内容完全相同。两包唯一不同的是 `package.json` 的 `dsh.bundle.patch` 字段，DSH 按它选择加载哪份 YAML。

| 插件包 | DSH 加载的 YAML | 加载后会发生什么 |
| --- | --- | --- |
| `dsh-for-codex-<版本>.tgz` | `./profile/web-mode.yml` | DSH 加载 `dsh-for-codex` 并传入 `sharedWeb: true`。插件复用已有的 Web 服务器和网页组件，在同一地址提供 DSH 和 Codex 两种模式。 |
| `dsh-for-codex-min-<版本>.tgz` | `./profile/cordis.patch.yml` | DSH 启动极简 Web 服务，加载 Codex 所需的网页组件和官方插件管理。会话与执行由 Codex 提供。 |

早期构建采用旧命名。安装旧包时，按包内 `package/package.json` 的 `dsh.bundle.patch` 字段核对上表中的 YAML。

两包都可以用 `dsh plugin --profile 名称 add 包路径` 安装。Profile 是 DSH 的一套具名配置，包含插件清单和设置。安装目标由 `--profile` 指定，在网页里安装时则是当前运行的 DSH 实例所用的 Profile。

### 在已有 DSH Web 中加入 Codex

在官方 Web 侧栏打开「插件 → 添加插件」，选择 `dsh-for-codex-<版本>.tgz` 并启用。刷新后即可从插件设置打开 DSH 和 Codex 两个入口，也可用 `?mode=dsh` 和 `?mode=codex` 直接打开相应标签页。

- 默认允许共存。侧栏「启用 Codex 模式」立即切换当前标签页，并更新随后打开且省略 `mode` 的页面默认值。其他标签页保留各自入口。
- 关闭「允许标签页使用不同模式」后，当前实例按已保存的默认值统一进入一个模式，侧栏开关可切换整个实例。
- 打开「Codex 独占」后，所有网页入口统一进入 Codex，侧栏开关隐藏，已有 DSH 标签页提示重新加载。后台 DSH 任务继续运行。退出独占时恢复之前的共存设置和默认值。
- 展开侧栏时也可点击品牌区的黑色徽标切换。徽标翻转后载入目标模式，系统开启减少动态效果时直接切换。
- Codex 标签页支持 DSH 插件热更新。停用或更新 DSH Codex 本身时，页面会提示重新加载。
- 「变更请求与工作树」的 Forge 面板仅在原生 DSH 标签页按插件设置加载。Codex 标签页使用自身的工作树选择与切换入口。
- Codex 标签页使用自己的自动化任务入口。使用 `$` 选择 Codex 技能，使用 `/ps` 或会话面板查看 Codex 后台进程。

### 单独启动极简 DSH Web 服务

极简网页专用于 Codex 会话，提供 DSH 的插件管理和热更新、快捷键设置、选中文本引用、消息凭据遮罩及远程设备配对。「插件 → 添加插件」管理当前 DSH Profile，「设置 → Codex 插件」管理 Codex 插件。设备配对使用当前实例的访问地址和监听设置。

需要 DSH 0.2.3-alpha.2、pnpm 和 Node.js 24.22.3 或更新的 24.x，或 Node.js 26.13.1 及以上版本。运行时依赖已登录的 Codex 和本机共享 App Server，插件使用 App Server 0.171.0 验证。若共享服务尚未启动，可运行 `codex app-server daemon start`。

选择带 `-min` 的包，把示例中的包路径换成实际的绝对路径。下面用 `codex` 作为 Profile 名称。DSH 会在安装时创建尚不存在的 Profile。

```sh
dsh plugin --profile codex add '/absolute/path/to/dsh-for-codex-min-<版本>.tgz'
dsh --profile codex --no-open
```

用浏览器打开 DSH 打印的完整链接。DSH 的 Web 服务器默认监听 `127.0.0.1:3190`，启动时传 `--port` 可指定端口。安装和启动使用同一个 `DSH_HOME` 和同一个 `--profile` 名称。更新时沿用原来的名称，安装新包后重启该实例。安装验收和迁移说明见 [给 AI 助手的安装指南](ai-install.md)。

## 从源码启动

在仓库根目录执行以下命令。`npm start` 每次都会先构建插件，再用仓库内保存的开发配置启动 DSH，并保留已有网页设置。新建开发配置时使用 `profile/cordis.patch.yml`。

```sh
npm ci
npm start -- --no-open
```

需要独立运行目录时，可传入 `--fresh-profile`，退出后会清理该目录。

插件默认用 `codex app-server daemon version` 查找共享服务。可通过 `DSH_CODEX_SOCKET` 指定 socket，通过 `DSH_CODEX_BIN` 指定 Codex 可执行文件。源码启动脚本可通过 `DSH_CODEX_DSH_BIN` 指定 DSH 可执行文件。

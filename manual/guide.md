# 安装与使用

## 已接入功能

- **工作区与会话。** 按 Codex 项目和工作目录组织会话。支持项目管理、会话新建与续接、改名、置顶、标记未读、归档、删除和排序，以及按工作区、标题和正文搜索会话。
- **历史与分支。** 分页历史、轮次跳转、子智能体会话和记录。打开会话标题栏的搜索，输入关键词并按 Enter，点击摘要即可跳到原消息。跳转后短暂标记消息，并高亮正文中能确定的那一处命中。支持从整条会话或指定轮次创建分支，也可编辑旧消息或回退历史。
- **消息与任务。** 实时跟随 Codex 已写入的消息和工具记录。支持图片粘贴和拖放、`@` 路径引用、排队和插话、审批与问答、任务清单，以及查看和停止后台进程。会话时间旁的蓝点表示仍有后台进程。
- **文件与预览。** 本地文件预览和行号定位、轮次文件差异，以及 Codex Visualize 交互预览。
- **设置与命令。** Codex 模型、推理等级和权限预设，以及 DSH 原生界面设置。命令菜单接入 `/status`、`/ps`、`/rename`、`/compact`、`/review`、`/plan`、`/goal` 和 `/export`。

## 使用细节

- **侧栏标识。** 插件启用时，展开的侧栏显示 Codex 图标和 **Codex on DSH** 字标，收起时显示 Codex 图标。
- **队列与归档。** 会话忙碌时，Enter 和发送按钮使用 DSH 设置中的默认发送方式，Ctrl/⌘+Enter 切换方式。待发消息可编辑、移除或改成插话。停止当前轮次也会暂停队列，可手动继续。归档会话可直接阅读和编辑草稿，发送、继续队列或确认查看队列时会解除归档。
- **审批与问答。** 网页和 CLI 都可处理审批与问答。网页会遮罩保密题的自由输入，整组草稿只留在内存中，关闭面板或刷新后清空。异步答复优先插入提问所在的运行轮次。若该轮仍是最新轮次，但已结束或暂不能接收插话，答复会进入队列。已保存的异步题目和选项会显示在归档会话的历史中。
- **模型与权限。** 未加载会话的模型选择随草稿保留，提交消息时应用。使用输入栏权限菜单切换后续轮次的权限，普通会话无需发送消息，归档会话随草稿应用。当前轮运行中、输入框有正文且下轮权限有变化时，会提示插话沿用本轮权限。悬停可查看本轮已记录的沙箱和审批策略。「通用」中的默认权限会在本网页新建会话时自动应用。指定默认预设后，只有已确认权限匹配的空白草稿才会被复用。
- **分支、回退与重发。** 从指定轮次创建分支会复制该轮的完整记录。编辑旧消息和删除本轮及后续对话适用于空闲或未加载的分页会话，有待发消息或历史变化时会中止。编辑旧消息会先回退，再在原会话重发。回退保留工作区文件和已执行操作的影响。

  从归档会话创建分支时，确认后会取消原会话归档，再创建并打开新分支。
- **归档会话改名。** 从侧栏菜单或 `/rename` 打开改名弹窗。提交「取消归档并改名」会把新名称写回原会话，线程保持未加载。
- **删除项目或会话。** 删除项目会解除会话的项目归属，侧栏按工作目录重新分组。永久删除会话会移除该会话及其子智能体历史。两种操作都保留工作区文件。
- **自动标题。** 网页新会话的首条消息含正文时，Codex 会额外发起一次模型请求拟标题，失败时使用正文摘录。
- **命令与计划。** `/compact` 需要有历史的空闲会话。未加载会话存在待发消息时，先处理队列，再压缩或审查。`/plan` 直接切换后续轮次的计划模式，点输入栏标签的 × 退出计划模式。
- **目标。** 从命令菜单选 `/goal`，在同一个输入框填写目标并发送。Goal 模式内可从「+」菜单选择「设置目标预算」。悬停或聚焦 Goal 标签会显示 ×，点标签即可退出待提交的 Goal 模式并保留输入内容。目标保存后，使用 DSH 进度条暂停、恢复、编辑或清除目标，完成时进度条会收起。替换现有目标时会先确认。悬停进度条可查看 Codex 返回的用量和预算。
- **Visualize。** 预览需要 DSH Host 能读取源文件，并能使用本机的 Python 3 和 Codex 插件缓存中的 Visualize 渲染脚本。
- **技能。** 输入 `$` 查看当前目录下 Codex 可用的技能，也可直接键入 `$技能名`。发送和插话按实际执行目录解析技能。
- **插件与 MCP。** 在「设置 → Codex 插件」浏览、安装或卸载插件，按详情页提示授权 App。「设置 → Codex MCP」可查看服务与工具、重新加载配置或发起 OAuth 登录。会话中的标准 MCP 表单和授权请求可从标题栏处理，复杂表单与额外身份验证可在 CLI 完成。
- **Git worktree。** 在新会话输入栏打开「本地目录」菜单，可使用当前目录、从列表选择已有工作树，或展开「新建工作树」选择基准分支。已有会话空闲时，从输入栏的「工作目录」选择目标，确认后继续使用原会话。菜单、确认框和悬停提示统一使用相对项目路径或 `~/…`。工作树显示分支名，分离 HEAD 时显示短提交号。新检出在首次发送时创建，位于源仓库同级目录，使用分离的 HEAD。未提交改动留在各自检出中。若首发投递结果不明，可从输入栏打开目标会话检查。
- **导出会话。** 用 `/export` 或标题栏「更多操作 → 导出会话」复制或下载完整的已保存 Markdown。正文、代码块、可见工具记录和附件说明会保留，归档会话也可直接导出。

## 安装与更新

需要 DSH 0.2.3-alpha.2、pnpm 和 Node.js 24.22.3 或更新的 24.x，或 Node.js 26.13.1 及以上版本。运行时依赖已登录的 Codex 和本机共享 App Server，插件使用 App Server 0.171.0 验证。若共享服务尚未启动，可运行 `codex app-server daemon start`。

从 GitHub Actions 的 Build 工作流下载并解压 `dsh-chatgpt` artifact。也可在仓库根目录运行 `npm ci` 和 `npm run package:plugin`，使用 `artifacts/` 中的 `.tgz`。

```sh
dsh plugin --profile codex add /absolute/path/to/dsh-chatgpt-0.1.0.tgz
dsh --profile codex --no-open
```

用浏览器打开 DSH 打印的完整链接。默认监听 `127.0.0.1:3190`，可用 `--port` 改端口。安装和启动使用同一个 `DSH_HOME`。更新时沿用已有的 `codex` Profile，安装新包后重启实例。安装验收和迁移说明见 [给 AI 助手的安装指南](ai-install.md)。

## 从源码启动

在仓库根目录执行以下命令。`npm start` 每次都会先构建插件，再使用仓库内的 `codex` Profile 启动 DSH，并保留已有 Profile 和网页设置。新建的 Profile 通过插件组合包读取仓库中的默认配置。

```sh
npm ci
npm start -- --no-open
```

测试时可使用 `npm start -- --fresh-profile --no-open --port 3191`。每次都会创建一个独立的临时 DSH 运行目录，退出后清理。

插件默认用 `codex app-server daemon version` 查找共享服务。可通过 `DSH_CHATGPT_SOCKET` 指定 socket，通过 `DSH_CHATGPT_CODEX_BIN` 指定 Codex 可执行文件。源码启动脚本可通过 `DSH_CHATGPT_DSH_BIN` 指定 DSH 可执行文件。
